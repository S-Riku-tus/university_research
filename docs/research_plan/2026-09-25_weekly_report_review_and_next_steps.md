### 1.2 教授へ渡す前後に修正・補足すべき点

1. **Aが「なし」では、Oの結果が修士研究の判断へ接続されない。**
   - Aには、ピーク選別によって学習する入力―熱流束関係が変わったという解釈、現行選別を採用しない理由、説明性を何に使うかを書く。
2. **確認事実と原因解釈を分ける。**
   - 「弱音・高熱流束の94秒を除外した」「ONB近傍RMSEが悪化した」は確認事実である。
   - 「弱音でも高熱流束になり得る対応を学べなくなり、共有回帰関数が低値側へ動いた」は結果と整合する原因解釈であり、OではなくAへ置く。
3. **「全帯域で低値側へ移った」とは書かない。**
   - 今回確認したのは熱流束領域別の残差変化であり、全周波数帯それぞれの条件付き出力低下を確認したわけではない。「評価集合全体の回帰関係が低値側へ動いた可能性」とする。
4. **「ONB近傍とONB以降が約50 kW/m²悪化」を一括りにしない。**
   - 近傍RMSEの悪化は3 seedで+26.1、+72.9、+60.5 kW/m²、平均約53 kW/m²である。近傍外ONB以上については二乗誤差が全seedで増えたと記載し、同じ約50という数値を流用しない。
5. **従来の重み計算を「コードがうまくできていなかった」と断定しない。**
   - `inner_holdout`は仕様どおり動作したが、本人が主に評価したかった全WAV K-fold方式ではなかった。従って「従来比較は目的とする方式と異なるため、アンサンブルの最終判断には使わず、`performance_kfold`で再評価する」と書く。
6. **ピーク閾値、アンサンブル方式、学習noise方針を同時に変えない。**
   - 同時に変えると改善・悪化の原因を特定できない。まず選別なしでアンサンブル方式を確定し、その後にピーク選別だけを変える。
7. **clean-onlyとmatchedを「どちらが言いやすいか」ではなく、答える研究質問で選ぶ。**
   - clean-onlyは未知の雑音を受けた固定モデルの耐性を調べる。
   - matchedは評価と同じnoise条件を学習にも与えた場合の適応性能を調べる。
   - 両者は異なる利用状況であり、同じ「ノイズ耐性」として混ぜない。

## 2. 現時点で固定できる研究上の判断

### 2.1 ピーク選別

確認事実:

- 2.1–2.5 kHzの最大Welch PSDが`1e-9`未満であるONB以降の94秒を、学習1080秒から除外した。
- 選別後、ONB前の正方向バイアスは全seedで減った。
- ONB近傍RMSEは全seedで悪化し、近傍外ONB以上の二乗誤差も全seedで増えた。
- 全域R²差はseedで符号が揃わず、全体性能の一貫した改善はなかった。

現時点の判断:

- `1e-9`選別は今後の基準条件には採用しない。
- 最も整合する解釈は、弱音でもONB以降となる学習例を除いたことで、共有回帰関数が低値側へ移り、ONB前の過大予測とONB以降の過小予測の間で誤差が移動したというものである。
- この解釈は領域別残差からの原因仮説であり、「2.1–2.5 kHzピークが弱い各評価秒で必ず出力が低下した」と直接確認した結果ではない。

### 2.2 説明性手法

- TreeSHAPは、RFの個別予測をPCA成分ごとの符号付き寄与へ分解し、予測値への再構成を検算するために使う。
- IGは、深層モデルで基準入力から対象入力までの予測差を、入力位置ごとの符号付き寄与として調べるために使う。ただし、数値収束とbaseline感度を満たした結果だけを使用する。
- Grad-CAMは、AlexNetの最終畳み込み層が反応する粗い正方向の領域を見る補助図として使う。細い帯域、負方向寄与、誤差原因の主証拠にはしない。
- 共通周波数帯マスクは、全モデルへ同じHz帯の変更を与え、予測値とONB領域別誤差の変化を比較するために使う。ゼロ置換の分布外影響と、物理的因果性を区別する。
- 4手法を横並びにして優劣を決めるのではなく、内部寄与、入力位置、粗い活性位置、共通帯域感度という別の問いへ割り当てる。

### 2.3 アンサンブル

- 今後の主方式は、全学習WAVを元WAV非共有5-foldで一度ずつ検証側へ回し、結合したOOF予測の単体R²から1組の重みを作る`performance_kfold`である。
- `performance_kfold`の条件と実装方針は作成済みだが、9/25時点で本実行結果はない。
- 従って、今回の教授向け報告では、`performance_kfold`によるアンサンブルの有効性や失敗原因をまだ結論として書かない。

## 3. 先に決めるべき主研究質問

全条件runを開始する前に、アンサンブルで答えたい雑音問題を次の二つに分ける。

### 問いA: 未知雑音への耐性

> cleanデータだけで学習した固定モデルと固定重みを、別日のcleanおよび複数SNRへ適用したとき、アンサンブルは単体モデルより性能低下を抑えられるか。

- 学習方針: `clean_only`
- 主張可能な範囲: 学習時に含めなかった評価noiseへの固定モデルの耐性
- 「ノイズ耐性」「雑音による劣化抑制」を中心にするなら、この問いが主比較として自然である。

### 問いB: 既知雑音条件への適応

> 評価と同じnoise条件を学習データにも与えてモデル・前処理・重みをnoise別に再推定したとき、アンサンブルは単体モデルより良いか。

- 学習方針: `matched`
- 主張可能な範囲: 同種・同SNRのnoiseを学習に利用できる場合の適応性能
- 未知noiseに対する固定モデルの耐性とは呼ばない。

### 推奨する位置づけ

本人の修士研究の表現が「雑音下の性能低下をアンサンブルで抑える」であり、実運用時にnoise別再学習を前提としないなら、**問いAのclean-onlyを主比較、問いBのmatchedを補助比較**とするのが論理的である。ただし、最終的な主従は教授へ相談してから固定する。

現在作成済みの`2026-09-25_matched_performance_kfold_fixed_epoch.json`は問いB用である。問いAを主比較にする場合は、このmatched本実行を始める前に、同じ分割・epoch・seed・評価noiseで`training_noise=clean_only`とした別条件を作り、実行順を決める。

- 主比較の学習noise方針を、結果を見る前に記録する。

### 段階1: `performance_kfold`の実装監査

本実行の前に、小さい動作確認で次を検査する。

1. 18学習WAVが5-foldで4、4、4、3、3本の検証側へ分かれる。
2. 全foldで学習側と検証側の元WAV共有が0である。
3. 各学習chunkに、自分を学習に含めないOOF予測がモデルごとにちょうど1個ある。
4. foldごとに重みを作らず、全OOF予測を結合してモデルごとに1個のR²を求める。
5. 重みは`normalize(1 / max(1-R², 1e-6))`で1組だけ作られる。
6. 評価日のラベルが重み、epoch、方式選択へ入っていない。
7. 最終モデルは全学習WAVを用い、200 epoch固定で再学習される。

終了条件:

- 上記7項目がmanifest、fold記録、OOF件数、重みCSVで確認できる。
- 動作確認結果を、本性能の結果として報告しない。

### 段階2: 選別なし・主noise方針での本比較

まず次を固定する。

- 周波数上限: 22 kHz
- 音響選別: なし
- epoch: 200固定
- seed: 42、43、44
- 単体: RF、CNN＋時間token Transformer、AlexNet
- 統合: `performance_kfold`、`simple_equal`
- 評価noise: clean、0、−4、−8、−12、−16、−20 dB
- 評価日をepoch、重み、方式の選択に使用しない

問いAを主とする場合、cleanでモデル・前処理・重みを一度だけfitし、同じ状態を全評価noiseへ適用する。問いBを主とする場合、noiseごとに独立fitする。両者を実行する場合も結果表と結論を分ける。

### 段階3: 結果を見る前に評価基準を固定

主評価:

- 全域RMSEと、cleanから各SNRへのRMSE増加量または比率
- RF、最良単体、等重みとの比較

安全性:

- 特定SNRでRFより大幅に悪化していないか
- seed平均だけでなく、各seedで悪化方向が一致していないか

ONB関連:

- ONB前、ONB近傍、近傍外ONB以上のRMSE・残差
- 誤報、見逃し、F1を併記し、Recall単独で改善としない

安定性:

- seed間の重み幅
- SNRごとの勝敗
- 単体モデルの残差相関と、統合で訂正・追加した誤り

暫定成功基準として、7 SNR平均RMSE、最良単体2%以内の条件被覆、RFからの最大悪化率を使用する案がある。ただし数値閾値は教授と相談し、結果を見る前に確定する。

### 段階4: `performance_kfold`の採否判断

- `performance_kfold`が複数seed・複数SNRで等重みとRFを改善する: 主方式候補として残し、別日条件へ進む。
- 等重みと同程度で重みが不安定: 複雑な性能重みを採用せず、等重みを基準候補とする。
- RFが一貫して最良: 現行3モデルでは雑音下の統合利得がないと判断し、重み探索より深層単体の雑音頑健化を優先する。
- cleanでは改善するがnoiseで悪化する: アンサンブル一般の失敗ではなく、noise下で単体誤差の多様性が失われる問題として扱う。
- 3モデルが同じ標本を同じ方向へ誤る: 凸結合だけでは訂正できないため、追加の重み方式だけで解決しようとしない。

### 段階5: ピーク選別は一因子比較として再検討

アンサンブル方式と主noise方針を固定した後にのみ行う。

候補条件:

- 選別なし
- 既存`1e-9`
- 強い閾値`1e-8`
- 各閾値と同じ秒数をランダムに除外する対照

比較上の注意:

- 閾値は学習日データだけから定義し、評価日成績を見て連続的に調整しない。
- 同数ランダム除外により、音響条件と単なる標本数・更新回数減少を分ける。
- 全域性能だけでなく、ONB前改善とONB以降悪化の誤差移動を確認する。
- 6/18は既に研究判断に使用しているため、閾値探索の探索用評価と最終的な独立検証を同一視しない。

終了条件:

- 選別が複数seedでONB近傍・高熱流束側を悪化させず、選別なしおよび同数ランダム除外より一貫して良い場合だけ採用する。
- 改善しない場合は閾値探索を終了し、「弱音のONB以降標本を除くと誤差が低値側へ移る」という限界を結果として残す。

### 段階6: 説明性は最終候補runの成功・失敗原因へ使う

1. 学習済みモデル、前処理、重み、全秒予測を保存する。
2. 同一モデル上で、統合が最良単体を訂正した秒と、統合が悪化させた秒を事前規則で選ぶ。
3. まず単体残差と重みで統合誤差を数値分解する。
4. 共通周波数帯マスクで、同じ帯域変更に対する全モデルの予測変化を確認する。
5. TreeSHAPはRF内部の寄与、IGは収束・baseline感度に合格した深層入力寄与、Grad-CAMはAlexNetの粗い補助図として用いる。
6. 説明図だけから気泡音を同定せず、修論ではモデル依存性・noise依存性・数値的限界を記載する。

### 段階7: 必要な場合だけmatched比較と追加方式へ進む

- clean-onlyを主比較とした場合、matchedは「既知noiseへの適応でどこまで回復するか」という副比較として行う。
- matchedを主比較とした場合も、clean-onlyを固定モデルの耐性診断として別に示す。
- `performance_kfold`で単一R²重みの限界が残り、モデル間の補完を直接扱う必要が明確になった場合だけ、同一OOFを共有した`subset_equal_cv`または`crossfit_shrinkage_stack`を比較する。
- 方式を増やす前に、「結果によって次の判断が変わるか」を確認する。

## 5. 9/25報告のA・Pに最低限追加する内容

### Aの記載案

- 2.1–2.5 kHzピーク選別により、弱音でもONB以降となる学習例が除かれ、モデルの回帰関係が低値側へ移った可能性がある。その結果、ONB前の過大予測は減った一方、ONB近傍以降の過小予測が増えたと考えられる。
- 現行`1e-9`選別は全域性能を一貫して改善せず、ONB近傍・高熱流束側を全seedで悪化させたため、今後の基準条件には採用しない。
- 説明性手法は、TreeSHAP、IG、Grad-CAM、周波数帯マスクを同じ重要度指標として比較するのではなく、モデル内部の寄与、入力位置、粗い活性位置、帯域変更への感度という異なる問いへ使い分ける。
- アンサンブルの有効性は、本人が主に想定する`performance_kfold`の本結果が得られてから判断する。

### Pの記載案

- まず音響選別なしで`performance_kfold`のOOF件数、元WAV非共有、重み計算、評価日未使用を監査する。
- 主たる研究質問を未知noiseへの耐性とするか、既知noiseへの適応とするかを教授と相談し、clean-onlyとmatchedの主従を結果を見る前に固定する。
- 固定した主noise方針で、RF、深層2モデル、等重み、`performance_kfold`を7 SNR・3 seedで比較する。
- その結果でアンサンブル方式を固定した後、必要な場合だけピーク選別なし、`1e-9`、`1e-8`、同数ランダム除外を一因子比較する。
- 最終候補runで保存モデルと全秒予測を用い、アンサンブルの成功・失敗例を説明性手法と残差分析で対応付ける。

## 6. 教授に確認する事項

1. 修士研究の主たる雑音問題を、clean学習モデルの未知noise耐性とするか、noise条件別に学習できる場合のmatched適応性能とするか。
2. アンサンブルの達成条件を、平均RMSE、最良単体との実質同等範囲、RFからの最大悪化、ONB誤報・見逃しのどの組合せで定義するか。
3. 現行`1e-9`選別を不採用として終了するか、機構確認のため`1e-8`と同数ランダム除外まで行う価値があるか。
4. 説明性を「物理的な有効帯域の確定」ではなく、「単体・統合モデルの成功・失敗要因を調べる補助」と位置付けてよいか。
