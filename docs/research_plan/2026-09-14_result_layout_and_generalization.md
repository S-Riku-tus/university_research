## 学習方針の選択

`code/run_ensemble_regression_onb.py` の設定欄に以下を追加した。

```python
"learning_policy": {
    "split_mode": "within_day",
    "training_noise": "matched",
},
```

| split_mode | training_noise | 学習・評価 |
|---|---|---|
| within_day | matched | 従来方式。同日の元WAVを分離し、各ノイズで学習・評価 |
| within_day | clean_only | 同日の学習側WAVの無雑音で学習し、学習外WAVの各ノイズ版を評価 |
| leave_one_day_out | matched | 他の日の同じノイズで学習し、1日全体を評価 |
| leave_one_day_out | clean_only | 他の日の無雑音で学習し、評価日の各ノイズ版を評価 |

既定値は従来方式。別日評価を使う場合は `data.experiment_names` に2日以上が必要で、1日しか有効でなければ学習前に具体的なエラーを出す。2日指定なら一方で学習・他方で評価し、役割を交換する。3日なら2日で学習・1日で評価する。`run.folds` は日内GroupKFold用で、別日評価では評価日ごとに1分割となる。

clean_onlyでは、周波数・パラメータ設定・外側分割ごとに単体モデルを一度ずつ学習する。同じモデル、目的変数scaler、PCA、内部holdoutから得たアンサンブル重みを、全評価ノイズで共有する。内部holdoutの一時モデルの学習は別途必要だが、これも評価ノイズごとには繰り返さない。

ノイズ間の対応は `(実験日, source_wav_id, chunk_index)` で取る。WAV・chunk集合、熱流束ラベル、時間区間が一致しなければ停止する。内部holdoutも含め、実験日と元WAV IDの組で学習／評価の重複を防ぐ。PCAと目的変数scalerは学習側だけで適合させる。

別日評価のONB指標には評価対象日の登録済み閾値を用いる。これは未知日に自動でONB閾値を決める機能を実装したという意味ではない。評価ラベルで重みを決めるval_fold_legacyは一般化評価で使用できない。

一般化評価は混在を防ぐため、実行日フォルダ名に次の短い識別子を付ける。その中はすべて同じ「周波数／ノイズ」の構造になる。

| 方針 | 実行日フォルダの末尾 |
|---|---|
| within_day + matched | 従来のまま |
| within_day + clean_only | `__wd_clean` |
| leave_one_day_out + matched | `__lodo_matched` |
| leave_one_day_out + clean_only | `__lodo_clean` |

`run_manifest.json` に学習・評価の日付とデータパスを、`split_manifest.json` に各foldの学習WAV・評価WAV・評価chunk添字・学習実行ID・内部holdout誤差を記録する。同じcleanモデルを使ったノイズ条件では学習実行IDが一致する。処理がすべて終わったら `completed.json` を保存する。

全ノイズが完了していれば再学習しない。clean_onlyの一部ノイズだけが未完了の場合は、モデル本体をディスクへ保存していないため、その学習に属する全ノイズを再計算する。以前のモデルと新しいモデルの予測を同じclean学習の曲線へ混ぜないための処理で、該当する集計行も置き換える。異なる学習設定はhashと保存先で分離する。

chunkと元WAVの評価は4方針すべてで同じ予測から保存する。別日評価の1日分から日間の標準誤差は推定できないため、ノイズ曲線には誤差棒を付けない。従来の汎用集計CSVでは単一foldのSE欄は0になるが、これは不確かさが0という意味ではない。日間のばらつきは複数の評価日の結果を使って今後評価する。

## 今回の曲線から読み取れること

22 kHz・WAV中央値のR²は以下のとおり。

| モデル | 無雑音 | SNR 0 | SNR −20 |
|---|---:|---:|---:|
| RandomForest | 0.9139 | 0.9133 | 0.9214 |
| CNN＋Transformer | 0.9618 | 0.9479 | 0.9426 |
| AlexNet | 0.9571 | 0.8886 | 0.9068 |
| inner_holdoutアンサンブル | 0.9596 | 0.9298 | 0.9390 |

この試行ではCNN＋Transformerが各点で最高であり、アンサンブルが必ず上回る結果にはなっていない。ノイズ増加に対して単調低下するモデルと、途中で回復するモデルがある。今回は各ノイズで学習し直す従来方式の結果なので、同一のcleanモデルが未知ノイズに耐えたとは解釈しない。

3 kHz・22 kHzのWAV中央値による連続ROC-AUCは、単体3モデルとinner_holdoutの全点で1.0。一方、二値化後AUCには0.9375と1.0の差がある。前者は正例・負例の予測順位、後者は登録閾値で二値化した判定に対応するため、R²低下や閾値近傍の誤判定と両立する。AUCが水平なことを作図不具合とは判断しない。
