# リポジトリ管理方針

更新日: 2026-09-15。使い慣れた配置と原資料を保ち、入口と記録の役割を明確にする。

## 配置の役割

| 場所 | 役割 |
|---|---|
| `code/` | 現行実行・共通処理・過去コード |
| `docs/` | 研究目的、現在地、年間計画、索引、運用メモ |
| `configs/` | データ仕様・実験条件の記録。現行コードへ自動適用する設定ローダーではない |
| `experiments/` | 結果・検証・解釈の固定記録 |
| `templates/` | 繰り返し使う文書形式 |
| `研究進捗報告/` | 週次報告・発表・論文輪講・学位論文等の原本 |
| `Pool_boiling/`、`water_flow/` | データ・生成結果・ノイズ音源の本体 |
| `archive/`、`trush_box/` | 旧実装や退避物 |

`High_speed_compare/`は[6/22の整理](storage_cleanup_2026-06-22.md)で削除された履歴上の場所で、現存する入口として案内しない。

## 研究作業の進め方

1. [現在地](research_status.md)で本人の最新希望・締切・完了状態を確認。
2. 必要な[コード](code_map.md)・[データ](data_inventory.md)・元結果を読む。
3. 実験条件を変更する場合、元条件と比較したい問いを記録。設定と実際の完了を分ける。
4. 結果を`experiments/YYYY-MM-DD_.../`に固定し、予測・指標・manifestへの参照を残す。
5. 現在地を更新し、[進捗索引](progress_index.md)に判断の変化を追記。長期計画が変わったときだけ年間計画を更新。

存在しない`docs/experiment_log.md`への追記はしない。[notes/experiment_log.md](notes/experiment_log.md)は実験記録への案内であり、数値を二重管理する場所にしない。

## Gitと結果の管理

コード、Markdown、Notebook、設定、原資料、軽量な指標・代表図を管理する。大量の配列、全画像、モデル重み、ログ・キャッシュは原則Git対象外。現行の除外は[.gitignore](../.gitignore)を確認する。

Git対象外の重要runにも、条件・完了範囲・評価単位・主要値・元パス・SHA-256を`experiments/`へ残す。モデルの設定上のepochs/batchと、OOM等を経た実際の学習条件を区別する。`run_manifest.json`やフォルダだけで学習完了とは判定しない。

日付付きスナップショットは報告時点の証拠。後日の再計算は別ディレクトリへ保存し、旧記録には訂正・後継リンクを付ける。元CSVを都合のよい最新値へ上書きしない。

## 古い情報の扱い

原資料・失敗例・過去の判断は保持し、[文書案内](document_index.md)から更新先を明示する。現行案内は上書き更新してよいが、過去の結果の数字と解釈は時点を残す。資料の移動・改名は参照の確認を伴う作業として行い、今回の整理では実施しない。

容量整理は[データ索引](data_inventory.md)から対象を具体化する。古い、精度が低い、使っていないように見える、という理由だけで生WAV・動画・原資料を削除しない。

## 更新判断の最小ルール

現行の目的・現在地・運用メモ・未提出草稿は、本人の希望と最新の固定根拠に沿って本文を更新する。日付付き分析・提出済み原本は保存し、変わった判断と後継を注記する。汎用テンプレートには、今回限りの数値ではなく再発を防ぐ確認項目を加える。

新しい解析の終了時は、現在地→進捗索引→発表準備中のSOAP/構成案を揃える。改訂前後の内容・対象範囲は[文書監査](audits/2026-09-15_document_consistency/README.md)で追える。[原資料ガイド](original_document_guide.md)と[解析手順](analysis_workflow.md)も参照する。
