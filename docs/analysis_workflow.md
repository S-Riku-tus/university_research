# 結果を研究上の判断へつなげる手順

更新日: 2026-09-15。繰り返し使う解析手順。現在の対象・進捗・次の一手は[研究の現在地](research_status.md)、目指す結論は[本人の研究仮説](research_plan/2026-09-15_master_thesis_hypothesis.md)を読む。本書にある追加比較は、すべてを実行する義務ではない。

## 1. 最初に「今回答える問い」を一つ決める

| 問い | 比較に必要な条件 | 結果の意味 |
|---|---|---|
| そのノイズ環境へ合わせて学習すると、どこまで予測できるか | matched。同じ元WAV分割で各ノイズを学習・評価 | 条件に合わせた学習を含むノイズ下性能 |
| 学習済みの同じモデルが、ノイズ増加にどこまで耐えるか | clean_only。モデル・PCA・scaler・統合重みを固定 | cleanからノイズへの転送性能 |
| 帯域上限を変えると性能がどう変わるか | 同じ録音・分割・ノイズ・モデル世代。元の周波数gridとresizeも記録 | 現行パイプラインにおける入力表現の比較 |
| 特定帯域がなぜ必要か | 共通Hz刻みで保持/除去。既存モデルのマスクと、加工後の再学習を区別 | 既存モデルの依存と、その帯域の予測情報を別に評価 |
| 統合で何が改善するか | 同じ評価標本、学習側で決めた重み、比較する単体 | 全域誤差・劣化量・ONB誤り・条件間変動のどこが改善するか |

matchedの非単調性だけでは実装不具合とも物理的な改善とも判定できない。clean_onlyも有限標本で必ず単調低下する保証はない。希望する曲線の形は仮説であり、採用条件を選ぶ唯一の基準にしない。

## 2. 対象を固定し、比較できることを確認する

- 収録日、解析日、データ版、run hash/instance、モデル構造、学習方針、実際のepoch/batch、元WAV数、閾値の出典を記録する。
- 完了印と必要な予測・指標・分割ファイルを確認する。設定上の条件数と完了数を別に書く。
- 複数ノイズ・周波数は元WAV/chunkの対応と外側分割を照合する。別runの欠測を以前の値で補わない。
- 本人が対象外とした実行は監視・再解析へ追加しない。後日、追加結果の解析を依頼されたときに別スナップショットとして採用する。

記録先は[実験条件テンプレート](../configs/experiments/experiment_template.yaml)と[解析テンプレート](../experiments/_template/run_summary.md)。YAMLを編集しても主コードの設定は自動では変わらない。

## 3. 性能を三つの観点で読む

1. **絶対性能**: WAV中央値をpoolしたR²・RMSE・MAEを主表にする。chunkのfold平均/SEは別図で示す。
2. **劣化と補完**: 各方式自身の無雑音からの低下量と、各ノイズでの最良単体との差を併記する。無雑音の基準性能が低いだけで低下量が小さく見える場合を区別する。
3. **ONB**: 固定閾値での見逃し・誤警報・最初のONB点・近傍標本数を確認する。連続ROC-AUCと二値AUCを区別し、R²の改善を検知改善へ自動的に読み替えない。

比較対象を評価結果から選んだ場合は「事後的な最良単体との記述比較」と明記する。重み・閾値・帯域・方式の選択は学習側で行う。7ノイズ加工や60 chunksを独立反復数と数えず、fold間SEとseed/実験日による不確かさも区別する。

## 4. 非単調性や統合効果の原因を絞る

まず保存予測から、どのWAV・熱流束領域・foldの誤差が変わったかを見る。次に同じ区間の入力パワー、帯域内SNR、resize、残差の一致/相殺、統合のONB誤り訂正と追加を確認する。

原因を記録するときは次の3段階を使う。

- **確認した事実**: 例「−12→−16の二乗誤差減少が低熱流束の数本に集中した」。
- **整合する仮説**: 例「利用帯域や条件ごとの再学習が影響している可能性」。
- **識別する次の比較**: 例「複数seedで回復が続くか」「共通周波数gridで差が残るか」。

各比較は、何が出たらどの説明を支持/弱めるかを先に決める。1回の再計算、相関、マスクだけで原因確定としない。新しいモデルや大規模gridは、既存の比較で説明できない不足を具体化してから検討する。

## 5. 説明性は対象と信頼性を揃えて読む

[モデル・説明性メモ](notes/model_notes.md)の役割表を使い、次を確認する。

- TreeSHAPのPCA成分説明、IGのbaselineとの差、Grad-CAMの局在、マスクの感度を区別する。
- IGの寄与総和と出力差、絶対/相対誤差を確認する。安定したmapや綺麗な図だけで数値的な正しさを判定しない。
- 全集合のマスク評価と、意図的に選んだ代表chunkの画像を分ける。時間マスクの感度は気泡の発生時刻を示すものではない。
- deletion/insertionの面積は回帰出力を積分した量であり、分類のROC-AUCではない。符号・baseline・ランダム順位の比較を確認して読む。
- 物理的な気泡由来の同定には、同期観測や独立した実験上の根拠を必要とする。

## 6. 次の比較を選ぶ順序

**既存データでの原因検証**は、保存予測の誤差確認→代表条件の再現性/転送→必要な帯域・XAI検証→別日/独立ノイズへの拡張、を基本とする。IGの少数例検証は性能比較と並行して行える。モデル本体が未保存なら限定再学習を伴うことを条件書へ記す。

**新実験の準備**は別に進め、ONB前後の刻み、同条件反復、正解源、同期方法を先生と決める。既存データのすべての検証が終わるまで設備・測定設計を待つ必要はない。具体的に今着手するものは[現在地](research_status.md)で一つに絞る。

## 7. 終了時に残すもの
