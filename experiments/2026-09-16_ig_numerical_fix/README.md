# IGの数値積分・収束診断の修正

2026-09-16。本人から「寄与合計と予測差の不一致の意味を説明し、コードで修正できるなら修正してほしい」と依頼された。9/14の結果の解釈を起点とし、既存の学習結果・説明画像は上書きしていない。

## 不一致とは何か

入力xに対するモデル出力をf(x)、比較の基準画像bへの出力をf(b)とすると、IGの符号付き寄与は、理想的には `sum(IG) = f(x)-f(b)` を満たす（completeness）。真の熱流束と予測との誤差を比べる式ではない。また絶対値mapや画像表示用0–1正規化mapの合計を比べるものでもない。

例えば基準画像への予測が100 kW/m²、入力への予測が370 kW/m²なら、各画素が増減させた寄与の合計は270 kW/m²になるはず。これが数千倍違うなら、モデルの出力変化を数値的に分解できていない。画像を各々0–1に正規化して表示すると、その失敗が目で分かりにくい。

原論文: [Sundararajan et al., Axiomatic Attribution for Deep Networks, ICML 2017](https://proceedings.mlr.press/v70/sundararajan17a.html)。completenessは数値監査に使える必要条件であり、物理的解釈の正しさや各画素の正確さを保証する十分条件ではない。

## 原因の切り分け

確認したデータの流れは、power入力→モデル内log変換→正規化熱流束出力→IG→出力MinMaxScalerの逆倍率→熱流束単位の寄与→符号付き配列・表示用絶対値map・CSV。

`_inverse_output_scale` の `1/scaler.scale_[0]` は差分の逆変換として正しい。オフセットは差分で相殺するため寄与に加えない。旧実装も絶対値をcompletenessに使っていたわけではない。

数値上の問題は、ゼロbaselineから生power上を直線的に動くIGを、**ゼロを含む等間隔64分割の台形則**で積分していたこと。モデル先頭の `log1p(p/1e-12)` の傾きは正のpで `1/(1e-12+p)`。ゼロ近傍の狭い区間で非常に急変する。

単純なf(p)=log1p(p/1e-12)、p=1e-6では、正しい寄与は13.8155。一方、旧64分割では約7817.236となる。最初の区間の端点勾配を大きな幅で代表させ、面積を過大に数えるためである。モデル側のReLU等でゼロの勾配が消える場合や途中の非線形性もあり、すべての例が同じ誤差倍率になるわけではない。

この数値障害を解析解のあるモデルで再現し、修正版では画素別の正負の寄与も解析解と照合した。**9/14の全179例の原因を当時のモデルで一件ずつ確定したわけではない**。当該6条件のrun配下にh5/keras/checkpoint index/SavedModelの学習済み重みは見つからず、当時のモデルを直接再計算することはできなかった。

## 実装した変更

- [積分本体](../../code/utils/explainability/spectrogram_explainers.py): Gauss–Legendre積分に変更。先頭にLogPowerCompressionがある場合、両端に点を密に置く変数変換を導入し、Jacobianも掛ける。**raw入力上の直線経路・ゼロbaseline・IGの定義は維持**。log座標で別の説明問題へ変えたものではない。
- 64点から倍増し最大4096点。`|sum(IG)-delta| <= 1e-6 + 1e-3*|delta|`（モデル出力単位）と、前回との符号付き寄与配列の相対L1変化1%以下の両方を確認する。初回の点数だけでは合格にしない。上限まで改善しても未収束なら明示する。
- 勾配計算は8入力ずつ。積分の累積・符号付き保存配列はfloat64。モデル本体の演算は従来どおりfloat32。有限でない入力・勾配・保存寄与は例外とし、ゼロへの置換で隠さない。
- 寄与合計を予測差へ合わせる事後的な倍率補正は行わない。この方法では局所寄与の誤りが隠れるため。
- [学習時との接続](../../code/utils/explainability/training_integration.py): サンプルごとに `integrated_gradients_diagnostics.json` を保存。点数ごとの誤差・map変化・最終判定・単位倍率を記録する。
- CSVに `ig_numerical_converged` と `ig_nodes` を追加。画像にも数値収束の判定を表示。摂動安定性・最終層ランダム化のCSVにも、比較元・比較先のIG収束判定を付ける。
- 出力完了確認では、旧CSVだけでは新診断が出力済みとは扱わない。未収束であることを記録済みの計算は「出力済み」と扱い、自動再学習を無限に繰り返さない。
- [主設定](../../code/run_ensemble_regression_onb.py)へ `ig_max_steps / ig_batch_size / ig_rtol / ig_atol / ig_map_rtol` を追加。モデル・訓練・アンサンブル予測の数式は変更していない。

両端への配置の数式: `a(t)=expm1(t*log1p(r))/(2r)`（左半分）、右半分は`1-a(t)`。重みには `da/dt=log1p(r)*exp(t*log1p(r))/(2r)` を掛ける。rは先頭log層のscaleと入力・baselineの範囲から決める。経路のたどり方の速度だけを変えるため、十分収束したときの画素別IGも元の直線経路と同じ。混合した増加/減少画素や非ゼロbaselineも試験した。

## 検証

[8件の専用テスト](../../tests/test_integrated_gradients.py)で、解析解、広いpower範囲、負の寄与、符号相殺、ゼロ出力差、非ゼロbaseline、複数channel、batchサイズ不変性、非線形相互作用の独立したSciPy積分との照合、未収束の警告、熱流束への逆変換、CSV/JSON、補助診断、ランダム化後の重み復元、旧出力の識別を確認した。

出力完了確認を含む最終コードで、既存テストを含む52テストが成功（25.905秒）。構文確認・`git diff --check` も成功。

[数値検証スクリプト](verify.py)と[検証結果](numerical_verification.json)には、以下を別々に保存する。

1. 解析解のあるlog和モデル: 正解39.8380942、旧積分789085.0395、修正版39.8380935。解析解に対する相対誤差は約1.70e-8。
2. 06.11・22 kHz無雑音の実入力（9/14・fold1・ONB代表chunk）と、現行CNN＋Transformer/AlexNetの**ランダム初期化モデル**による構造上の数値試験。学習はしていない。初回1024点で両モデルが未収束と判定されたため、上限を4096へ増やす追加確認を記録する。

ランダム初期化の検証は、実際の入力スケール・ネットワーク演算で計算が働くことの確認であり、学習済みモデルの説明性検証を代替しない。CPUで実施。

最終検証値（下の相対誤差は比率ではなく百分率）:

| 構造＋実入力、ランダム初期化 | 旧64分割の相対誤差 | 修正版の相対誤差 | 点数 | map相対L1変化 | 総合判定 |
|---|---:|---:|---:|---:|---|
| CNN＋Transformer | 38.6373% | 0.09348% | 2048 | 0.77332% | 収束条件を満たす |
| AlexNet | 120.9525% | 0.51109% | 4096 | 0.34937% | **合計誤差が厳しい許容値を超え、未収束** |

AlexNetは大幅に改善したが、今回設定した許容値には届かなかった。2048点で約0.181%だった合計誤差が4096点で約0.511%となり、点数を増やせば誤差が単調減少するわけでもない。基準を後から緩めて成功扱いにはしていない。修正の達成範囲は「急峻なlog変換で旧積分が破綻する問題の対処、精度改善、未収束を識別できる出力」であり、全モデル・全入力の数値問題が解消したという結論ではない。baselineからの予測差の小さいランダム出力での相対値と、学習済みの熱流束出力での実用誤差も分けて評価する必要がある。

## 次回の研究実行での使い方

新たに起動して説明性を生成する実行では修正版が使われる。既に起動中のPythonプロセスには自動反映されない。旧runの図は旧計算のままなので、新しい結果と区別して保持する。

今回 `retrain_completed_runs_for_xai=False` は変更していない。完了済みrunを自動で学習し直す設定にはしていない。当時の重みが別の場所に残っていれば、同じモデルで説明性だけ再計算するのが最も直接的。ない場合は、対象を明示した新runで必要なモデル・foldを再学習し、説明性を新規保存する必要がある。新runを9/14の同一モデルの修正画像とは呼ばない。

最初は少数例でJSONの `converged`、completeness誤差、map変化を確認する。上限でも未収束ならそのmapから強い結論を出さず、点数・入力経路の数値挙動を追加診断する。4096点は計算上限であり、すべての学習済みモデルでの成功保証ではない。説明性の計算時間は旧64分割より増える。

数値が合っても、ゼロ入力という比較基準の物理的妥当性や、モデルが気泡由来の成分を見ているかは別の問いである。この修正は説明図を研究に使うための数値的な土台を整えるもので、モデルの回帰精度やアンサンブルの悪化を直接改善する修正ではない。
