# 3 kHz採用条件のmatched対照：回帰・ONB・誤り補完

解析日：2026-10-03。本人が実行したmatchedの保存予測を、対応するclean_onlyと比較した。主コード・設定・学習済み出力は変更せず、新規学習も実行していない。

## 結論

matchedは0〜−12 dBの全域RMSEとnoise全6条件のRecallを改善した。ただし、−16/−20 dBの全域RMSEは改善せず、ONBちょうどの過小予測は悪化した。**「noiseを学習すれば全領域が改善する」「matchedなら常に統合が最良」とは言えない。** clean_onlyは未学習noiseへの耐性、matchedは各noiseへの再学習を含む適応性能を示すため、両系列を保持する。

−20 dBではRF単体が大きく改善した一方、統合の残る見逃し49件中45件は全3モデルの共通失敗だった。これは誤り方の活用を考える重要な根拠であり、現在の3モデルの非負平均を調整するだけでは訂正できない範囲がある。

### 不確かさ

[36 WAV対応bootstrap](cluster_bootstrap_rmse_deltas.csv)を5000回実施した。matched − clean_onlyの全域RMSE差の95%区間は、−4 dBで−17.98 [−26.42, −10.03]、−8 dBで−9.86 [−13.97, −5.65]、−20 dBで+0.19 [−8.79, +9.73]。中程度noiseの一部には対応標本上の改善があるが、強noiseの小さな全域差を確かな改善/悪化と断定しない。

これは固定済みモデルに対するWAV標本の変動であり、再学習seed・新しい実験・独立noiseの変動ではない。ONB近傍は2 WAVしかなく、このbootstrapで近傍の一般的優劣を保証していない。

## 3. どこが変わったか：−20 dB

[領域別指標](region_metrics.csv)は実熱流束で分けた事後診断であり、推論時に領域ラベルを入力する方式ではない。

| 実熱流束の領域 | n | RMSE clean_only → matched | matchedの平均bias | 二乗誤差の割合 clean_only → matched |
|---|---:|---:|---:|---:|
| 60 kW/m²未満 | 120 | 141.55 → 119.32 | +112.40 | 65.48% → 46.31% |
| 60 kW/m²〜ONB前 | 105 | 41.12 → 60.04 | −36.92 | 4.83% → 10.26% |
| ONB〜1.5×ONB未満 | 90 | 97.16 → 116.95 | −84.13 | 23.14% → 33.37% |
| 1.5×ONB以上 | 225 | 32.68 → 40.60 | −25.93 | 6.54% → 10.05% |

確認事実：低熱流束の過大予測は減ったが大きく残る。ONB前の上側、ONB直後、高熱流束側は回帰誤差が増え、低側の改善と相殺して全域RMSEはほぼ同じになった。高側のRMSEはONB直後より小さく、−20 dBの高側225 chunkに見逃しはないが、回帰としては完全ではない。

日別にも一律の改善ではない。6/11の全域RMSEは78.19 → 73.96、6/18は86.52 → 90.51。ONBちょうどは6/11で64.41 → 107.77、6/18で103.06 → 148.71と両日悪化した。

### Recall改善とONB近傍RMSE悪化が両立する理由

[段階別の平均・標準偏差・最小最大・陽性数](stage_profiles.csv)より。すべて各15 chunk。

| 日 | 実熱流束 | 平均予測 clean_only → matched | 陽性chunk数 clean_only → matched |
|---|---:|---:|---:|
| 6/11 | 221.51（ONB） | 158.70 → 116.52 | 0 → 0 |
| 6/11 | 266.91 | 208.19 → 211.11 | 6 → 10 |
| 6/11 | 315.47 | 249.03 → 275.47 | 9 → 12 |
| 6/18 | 271.68（ONB） | 170.79 → 136.65 | 0 → 1 |
| 6/18 | 322.11 | 184.79 → 179.81 | 0 → 4 |
| 6/18 | 376.32 | 305.76 → 349.64 | 11 → 14 |

ONBちょうどの平均予測は真値からさらに下がる一方、その後の段階で閾値を超えるchunkが増えている。例えば6/18の322.11では平均が下がっても標準偏差が35.98 → 90.15へ広がり、陽性は0 → 4になる。判定が正しくなったchunkと、過小予測が強まったchunkが併存するため、RecallとRMSEの方向は一致しない。

原因仮説として、noiseごとの再学習によって応答の偏りとchunk間変動が変わったことは整合する。しかし、利用した音響特徴・データ不足・学習不十分のどれが原因かは、この予測集計だけでは確定しない。

## 4. q100：大半は不変、一つの改善

[日別q100とg100](q100_source_day_thresholds.csv)。q100は「その実熱流束段階以降の全テストchunkがONB以上の予測になる最小段階」、g100はq100 − 日別ONB。真の発泡開始秒や将来の100%保証を示すものではない。卒論のCHF正規化指標と同一でもない。

- 6/11：両系列の全7条件でq100=368.98、g100=147.47。
- 6/18：clean_only全7条件とmatchedの6条件でq100=434.02、g100=162.34。
- 例外は6/18のmatched −12 dB：q100=376.32、g100=104.64。gapが57.70小さくなった。376.32の陽性数が14/15 → 15/15になったことによる。

従って、performanceの14日×noiseセル中13セルは不変、1セルは改善。−20 dBのRecall改善は両日のq100改善を伴わない。−12 dBでは6/18のONB前誤報も0 → 2件（同日FPR 1.67%）なので、この一つの早期化だけでONB性能全体の優越を主張しない。段階指標は1 chunkの残る見逃しでも次段階まで動く性質がある。

## 5. 単体・等重み・performanceと重みの意味

matchedの全域RMSE。日別ONB指標を含む全値は[指標CSV](metrics_source_day_thresholds.csv)。

| noise | RF | Conformer | AlexNet | 等重み | performance |
|---|---:|---:|---:|---:|---:|
| 無雑音 | 71.18 | 35.16 | 45.69 | 38.54 | 35.07 |
| 0 dB | 72.67 | 42.91 | 58.05 | 47.38 | 45.90 |
| −4 dB | 72.72 | 45.35 | 46.66 | 46.16 | 44.88 |
| −8 dB | 72.98 | 63.97 | 59.13 | 57.55 | 58.30 |
| −12 dB | 72.57 | 75.29 | 90.13 | 69.63 | 69.01 |
| −16 dB | 79.52 | 86.74 | 90.02 | 78.65 | 78.40 |
| −20 dB | 76.17 | 92.17 | 101.89 | 82.98 | 82.65 |

performanceは7条件中5条件で全単体より低いRMSE、6条件で等重みより低いRMSE。ただし0 dBはConformer単体、−8 dBは等重み、−20 dBはRF単体が低い。外側結果から選ぶ最良方式は事後的な診断であり、SNR別に外側テストで採用方式を選び直す運用を実装したわけではない。

noise6条件平均RMSEは、RF 74.44、Conformer 67.74、AlexNet 74.31、等重み63.73、performance 63.19。統合には平均的な回帰利得がある一方、performanceと等重みの差は0.54と小さい。強noiseでperformanceが常に最良という結論にはならない。

特に−20 dBのRFはclean_only → matchedで、RMSE 148.72 → 76.17、誤報216 → 1、見逃し0 → 46。従来のONB前の常時陽性に近い挙動を大きく抑えた。一方、matchedのperformanceはRFよりRMSEが6.48高く、対応WAV bootstrap区間も[+2.37, +10.90]。RFのFPRは0.44%に対しperformanceは0%、見逃しは46に対し49なので、RFと統合にも回帰/誤報/見逃しのトレードオフがある。

[重みCSV](weights.csv)ではRF/Conformer/AlexNetが無雑音0.220/0.426/0.354、−20 dBは0.329/0.403/0.268。RF重みは増えたが、−20 dBでもConformerが最大。これは[学習OOF](training_oof_metrics.csv)のRMSEがRF 92.43、Conformer 83.41、AlexNet 102.34だったことと整合する。外側のRF優位を無視して計算したバグではなく、学習OOFの順位と最終モデルの外側順位が一致しない例である。内部OOFはWAVを分離し、外側は既知WAV内chunkを評価するという難しさの違いもあるが、それだけを原因と断定しない。

−20 dBのperformanceはConformer単体の二値誤りを13件訂正し、正解を新たに誤りへ変えた件数は0。[訂正/追加](ensemble_corrections.csv)。統合が役立つ例はあるが、全モデル・全指標を常に上回るわけではない。

## 6. 誤り方向の活用：補完可能な誤りと共通失敗

[補完診断](complementarity.csv)と[残差の組合せ](residual_pairs.csv)は、正解を知る事後的な診断。実運用の新統合性能ではない。

−20 dB、ONB〜1.5倍の90 chunkでは：

| 診断 | clean_only | matched |
|---|---:|---:|
| 3モデルとも真値より低い | 28 | 54 |
| 真値が3モデル予測の最小〜最大に入る | 62 | 29 |
| performanceの見逃し | 64 | 49 |
| 上記見逃し中、少なくとも1モデルが陽性 | 64 | 4 |
| 上記見逃し中、全モデルが陰性 | 0 | 45 |

RFの同領域biasは+19.82 → −76.20、Conformerは−79.92 → −69.53、AlexNetは−149.96 → −115.84。RF/Conformerの残差相関は0.339 → 0.727、逆符号のchunkは54 → 24。RF/AlexNetも逆符号60 → 19に減った。matchedでRFの過大予測が改善した結果、ONB直後では3モデルが共通に過小予測する範囲が増えたことと整合する。

**既存の3予測がすべてONB未満なら、非負で和1の重みは入力ごとに変えても、その平均をONB以上へ上げられない。** matched −20 dBの見逃し45件はこの範囲にある。残り4件に補完余地はあるが、重み変更が他の正解を崩さない保証はない。出力補正、負の重み、別の基モデル等はこの制約の外だが、現在のperformance/等重みの単なる調整とは別方式になる。

また、低熱流束120 chunk中107 chunkはmatchedでも全モデル過大。これは「多様性を高めればすべて解消できる」結果ではない。

[学習側OOFの共通失敗](training_oof_complementarity.csv)でも、matched −20 dBのONB直後270 chunk中167が全モデル過小、134が全モデル陰性。問題は外側テストだけで見つかるものではなく、学習側診断でも検討できる。ただしOOFの個々の予測は別foldのモデルに由来するため、外側件数との直接比率比較を原因説明に用いない。

## 7. 解釈・未確認事項・次の識別比較

### 確認できたこと

1. noiseを学習することで中程度noiseの全域回帰と、noise条件の全体Recallを改善できた。
2. その改善は領域一様ではなく、強noiseのONBちょうどの回帰は悪化し、q100も大半が不変だった。
3. 統合には平均的な回帰利得とConformerの誤り訂正があるが、強noiseの最良単体を常に上回らない。
4. matchedは単体RFのnoise適応を改善する一方、ONB直後の共通過小予測を残す。全域の単体品質と、誤りの補完可能性は別に見る必要がある。

### まだ言えないこと

- matchedが最適な学習方針であること。採用値はclean由来で、seedは42の1回。
- 誤り多様性を使う新方式が自研究で有効なこと。現行方式の診断までで、新方式は未実装・未検証。
- 特定の周波数/時間特徴が原因であること。今回IG・SHAP・マスク等は再評価していない。
- 独立WAV/日/実水流音への一般化。本人が現在対象外とした評価を追加していない。

### 次の順序

1. **主比較を固定し、説明と修論へ移す。** clean_onlyとmatchedを同じ条件の2系列として保持。単体3＋等重み＋performance、全域/ONB/日別q100をセットにして、「学習していないnoiseへの劣化」と「学習しても残る領域別誤差」を説明する。現時点で3 kHz・1秒・選別なしや採用値を再変更しない。
2. **補完の説明を一段深める。** 現行の学習OOFを使い、単体MSEだけでなく残差積・過大/過小の共通率をまとめる。代表比較は無雑音・−8・−20 dBと、低熱流束/ONBちょうど/ONB直後。これは新方式を作る前に、何を改善できるかを明示するため。外側では代表chunkの特徴説明も照合するが、原因確定にはマスク等の応答検証が必要。
3. **新統合を試すなら一方式だけ。** 学習OOFの残差積を考慮する非負重み等を、3単体・既存performance・等重みと比較する候補とする。重み/モデル集合の選択は学習側のみ。真の熱流束領域・ファイル名・外側結果を使って推論時のモデルを選ばない。目標は補完可能な誤りでの利得であり、45件の共通陰性まで重みだけで救えると期待しない。既に見た同じ外側結果への反復適応は探索的検証として記録する。
4. **共通失敗の原因が絞れた場合だけ基モデル側を変える。** matchedのONBちょうどの低下がseedを変えても出るなら、ONB近傍の学習重み・入力特徴・出力校正等を一要因ずつ検討する。最初から大規模再チューニングへ進まず、どの結果がどの仮説を支持するかを先に決める。未知WAV/日は現在の必須実験へ戻さない。

この順序は教授と共有した「noiseによる精度逆転の解釈」「統合効果と説明性」という大きな研究問題を維持するための提案であり、局所Recallだけへ主目的を置き換えるものではない。修論目次案・既存の2週間準備は並行する。
