# 元WAV validation・音響選別・ONB・アンサンブル・IGの追跡監査

実施日：2026-09-24。既存成果物と現行コードを照合した。新しい学習runは実行していない。追加実験と同期映像は今後も取得できない。

## 1. 元WAV非共有validation

1本の元WAVから60個の1秒chunkが作られる。同じ元WAVのchunkを通常のランダムKFoldで学習側とvalidation側へ分けると、ほぼ同じ収録条件・熱流束・背景音を持つ兄弟chunkが両側へ入り、未知録音への一般化性能を過大評価し得る。

現行`wav_kfold`は、まず`source_wav_id`をfoldへ分け、そのWAVに属する全chunkをまとめてfit側またはheld-out側へ入れる。6/11の18 WAV・1080秒、3 foldなら概ね12 WAVでfitし6 WAVでvalidationする。同一foldで同じ元WAVは両側へ入らない。6/18はepoch・重み選択に使わず、最後の別日評価だけに使う。

## 3. 現行ONBでの2.1–2.5 kHzピーク再集計

入力は[`peak_features.csv`](../2026-09-16_peak_height_selection/peak_features.csv)の全2,940秒。特徴量はWelch PSDの`peak_2100_2500_psd`、単位はdigital amplitude²/Hz。現行ONB以降で閾値未満となる秒数を再計算した。

| 閾値 | 6/11（660秒） | 6/18（600秒） | 7/9（300秒） |
|---:|---:|---:|---:|
| 3e-11 | 86 | 68 | 14 |
| 5e-11 | 87 | 80 | 76 |
| 1e-10 | 87 | 87 | 83 |
| 3e-10 | 89 | 93 | 88 |
| 1e-9（現行C） | 94 | 106 | 91 |
| 3e-9 | 113 | 120 | 99 |
| 1e-8 | 154 | 146 | 106 |

全候補は[`threshold_candidate_counts.csv`](threshold_candidate_counts.csv)。現行`1e-9`は6/11で94/660秒、6/18で106/600秒、7/9で91/300秒を除くため、現在の正しいONBに対して意図どおりONB以降だけを選別している。

ただし分布は連続でなく、ONB直後に「ほぼ背景音の群」と「明瞭な2.1–2.5 kHzピークの群」が共存する。6/11では`3e-11`で既に86秒、`1e-9`でも94秒であり、閾値を約33倍変えても差は8秒しかない。特に221,505 W/m²の60秒は全て`1e-9`未満、266,908 W/m²は25秒、315,466 W/m²は9秒が未満だった。従ってCは、単に小さな測定ノイズを捨てたのではなく、「ONB以降でも弱い音を持つ境界標本」をまとまって削除している。

閾値の追加比較は次の順がよい。

1. `selection_off`：全1080秒。基準。
2. `1e-9`：986秒。既存C。弱音群を除く現行条件。
3. `1e-8`：926秒。境界群をさらに60秒除く強い選別。
4. 各選別と同じWAV・熱流束ごとの除外数を再現するランダム除外対照。

`5e-11`は「6/11のONB前最大値約5.2e-11を超える」という背景基準として説明しやすいが、除外87秒で`1e-9`との差が7秒しかない。まず高価な本学習を増やすより、既存`1e-9`を代表値にして`1e-8`とランダム対照を加える方が、閾値強度と標本数減少を識別しやすい。閾値は6/11学習データだけで固定し、6/18の結果を見て調整しない。

## 4. Cが直感どおりにならなかった理由

「ONB以降だけを削除するならONB前精度は変わらない」という直感は、ONB前とONB以降で別々のモデルを学習する場合には近い。しかし現行モデルは全熱流束域を1つの回帰関数で表すため、学習標本をONB以降だけから削除しても関数全体が変わる。

段階的には次の現象で説明できる。

1. 選別対象94秒は全て正しいONB以降だが、音響的にはONB前に近い弱音である。
2. 選別なしでは、モデルは「弱い音でも221–315 kW/m²になり得る」と学ぶ。
3. それを削ると、弱い音を低熱流束へ割り当てる方が損失を下げやすくなり、回帰関数が全体に低い側へ動く。
4. その結果、ONB前で元々あった過大予測は改善する。一方、弱音のONB直後は過小予測となり、近傍誤差が悪化する。

実測結果もこの説明と一致する。選別あり−なしの平均変化は、RFでONB前RMSE −38.1、近傍RMSE +80.5、ONBより上の近傍外RMSE +15.6 kW/m²、Conformerで−14.7、+37.0、+26.6、AlexNetで−26.7、+57.4、+13.3だった。ONB前の平均残差も全モデルで負方向へ48.5～82.7 kW/m²動いた。統合もONB前RMSE −21.7、近傍 +53.2、近傍外ONB以上 +16.3 kW/m²である。

さらに、RFでは選別後データでPCAを再fitするため座標系と木の分岐が変わる。深層モデルは全標本で共有する重みへの勾配が変わる。1080→986秒に減るため、epoch固定では1 epoch当たりの更新回数も約8%減る。したがって現在強く支持される主因は「弱音のONB以降境界標本を消したことで共有回帰関数が低い側へ動いたこと」だが、選別内容の効果と単なる標本数・更新数の効果を完全に分けるには、同数ランダム除外と更新回数を揃えた比較が必要である。

現状の結論は、`1e-9`選別が無意味ということではない。ONB前の過大予測を減らす代わりに、ONB近傍とそれ以降を悪化させるトレードオフがあり、近傍重視の現目的では標準条件に採用しない、である。

## 5. アンサンブルが常に優れない原因と次の比較

固定cleanモデルではRFのR²が無雑音/.850、−8/.858、−16/.870、−20/.856と安定した一方、CNN＋Transformerは.917→.527→−.276→−.931へ低下した。clean性能でCNN＋Transformerへ0.542の重みを与えたため、強ノイズで統合が頑健なRFを下回った。

−16 dBのONB前平均残差はRF +6.2、CNN＋Transformer +429.7、AlexNet +191.0、統合 +287.7 kW/m²だった。同じ方向の誤差は凸結合で相殺できない。従って直接原因は、(1) cleanで決めた重みがノイズ時のモデル順位変化へ適応しないこと、(2) 深層2モデルのONB前誤差が同方向で、多様性が不足すること、の2点である。

本人希望どおり、次は音響選別を切り、cleanだけで学習した同じ保存モデルを全SNRへ推論する。本実験条件は[`2026-09-24_clean_train_noise_inference.json`](../../configs/experiments/2026-09-24_clean_train_noise_inference.json)へ固定した。3 seedでRF、各深層モデル、等重み、現行の学習側`inner_holdout`重みを比較する。SNRごとに再学習しないため、谷が学習揺らぎ由来か、入力ノイズに対するモデル固有の応答かを分離できる。制限付き統合など新方式は、この結果を確認してから必要性を判断する。

## 6. IG未収束の原因と修正

従来IGはゼロraw-powerから入力までを直線補間した。モデル先頭の`LogPowerCompression(scale=1e-12)`はゼロ近傍で非常に急で、その後のReLU/MaxPooling等の折れ点も多数横切る。最大4096点でもcompletenessまたは連続地図差が基準に入らない主な数値的理由である。

現行コードへ`integrated_gradients_log_power`を追加し、既定をモデルが実際に学習するlog-power空間の直線経路へ変更した。旧raw-power経路は`ig_path_space=raw_power`で再現できる。保存済み1 epoch AlexNetと実データ1秒では、256点時のcompleteness誤差がraw `-0.001509`からlog `-0.000571`へ62%減り、地図変化量も`.0629`から`.0272`へ57%減った。log方式1024点では地図変化量`.00660`で1%基準に入ったが、completeness誤差`.000176`は現行0.1%相対基準に未達だった。

コード上の主要な数値問題は改善したが、完全収束を確認したとはまだ言えない。本学習モデルで複数baselineを比較し、completeness、連続解像度間の地図差、上位周波数帯の安定性を同時に確認する。閾値を緩めて見かけ上合格させない。
