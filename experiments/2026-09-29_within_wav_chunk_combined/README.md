# 6/11＋6/18統合データとWAV内chunk holdoutの実装記録

記録日: 2026-09-29

## 結論

本人が想定していた評価は、各WAVを丸ごと学習側またはテスト側へ置く方式ではなく、**各WAVの1秒chunkを指定割合で学習側とテスト側へ分ける方式**だった。変更前の`within_day`は前者だったため、後者を明示する`within_wav_chunk`を追加した。既存の`within_day`は、未知WAVへの一般化を測る別方式として残した。

6/11と6/18を物理的に複製・統合した実験フォルダも作成した。統合実験のONB閾値は、本人の指定どおり両日の確定値の算術平均とした。

## 分割の意味

`within_wav_chunk`では、seed 42を使い、各WAVの60個の1秒chunkから15個をテスト専用、残る45個を学習・内部検証用にする。学習側とテスト側で同じ`(実験, 元WAV, chunk_index)`を使わない。

統合フォルダでは、manifestの`source_experiment_name`と`original_source_wav_id`を使い、出典日ごとにseed 42の乱数列を独立に開始する。これにより単日runと統合runのテストchunkは6/11・6/18とも270/270一致し、統合学習の効果と評価標本の変更を混同しない。出典情報を持たない通常の単日データでは従来の分割結果を変えない。

したがって同一データの重複という意味でのリークはない。ただし、同じ録音WAVに固有の背景音、センサ状態、録音条件、熱流束ラベルは両側で共有する。この方式が測るのは**既知WAV内の未使用時間区間への補間性能**であり、未知WAV・未知実験日への一般化性能ではない。後者を主張するときは、既存の`within_day`（WAV丸ごとholdout）または`cross_day`を使う。

外側テストを分けた後、`performance_kfold`の重みと各モデルの内部評価は、学習側だけを使う元WAV単位GroupKFoldのままにした。外側テストchunkは、モデル学習・PCA・scaler・epoch情報・アンサンブル重みの決定に使わない。

## 統合データ

- 保存先: `Pool_boiling/Subcooling_20_degrees/0.3/2025.06.11_0.3_2_6.18_0.3_3`
- 元実験: `2025.06.11_0.3_2`, `2025.06.18_0.3_3`
- NPY合計: 226,800ファイル、約42.42 GiB
- 0.5秒: 151,200ファイル、約28.28 GiB。5周波数×7 noise＝35条件、各条件4,320 chunk（各日2,160、各WAV 120）
- 1秒: 75,600ファイル、約14.14 GiB。5周波数×7 noise＝35条件、各条件2,160 chunk（各日1,080、各WAV 60）
- 元名WAV: 36ファイル、熱流束名付きWAV: 36ファイル。いずれも出典日別のサブフォルダへ保存
- 測定メタデータ: 6ファイル
- manifest: 35個。出典実験、元のファイル名、元WAV ID・名前を追加
- コピー方式: 元データを変更しない独立ファイルコピー

NPY名は熱流束の数値prefixを維持し、その直後へ出典日tagを加えた。既存loaderによるラベル読取りを変えず、同名ファイルの衝突を防いでいる。`source_wav_id`にも出典日tagを付け、6/11と6/18のWAVを別groupとして保持する。

## ONB閾値

確定済みの日別閾値は次のとおりである。

- 6/11: 221,505.1102 W/m²
- 6/18: 271,677.6816 W/m²
- 統合値: `(221505.1102 + 271677.6816) / 2 = 246591.3959 W/m²`

平均閾値は、学部時代の統合方法へ合わせた今回の運用値であり、両日の物理的ONBが同一になったことを意味しない。日別ONBの違いを隠すため、最終的な修論主張では日別評価も併記する必要がある。

## 現在の初回実行条件

- 評価: `within_wav_chunk`
- 統合実験: `2025.06.11_0.3_2_6.18_0.3_3`
- 外側test: 各WAVの25%、seed 42
- 入力上限: 3 kHz
- noise評価: clean, 0, -4, -8, -12, -16, -20 dB
- 学習方針: `clean_only`
- アンサンブル: `performance_kfold`
- 内部fold: 3、元WAV単位
- epoch: 150

主コードの`data.chunk_seconds`は現在1なので、初回runは1秒データを使う。データフォルダ名の`{chunk_tag}`はこの値から自動解決されるため、0.5秒を使う別runでは`chunk_seconds`だけを0.5へ変更する。

`learning_policy`は、最初に`evaluation_mode`を選び、その下の`evaluation_settings`では選択した方式と同名の欄だけを編集する構成にした。

- `cross_day`: `train_experiments`と`test_experiments`
- `within_day`: `experiment`、WAV単位の`test_fraction`、seed、ONB層化
- `within_wav_chunk`: `experiment`、各WAV内chunk単位の`test_fraction`、seed

選ばれていない方式の欄は実行に影響しない。`within_wav_chunk`の`experiment`は1つの実験フォルダ名であり、単日フォルダにも今回の統合フォルダにも切り替えられる。

`clean_only`を最初にしたのは、現在の主問題である「clean学習モデルに未知noiseが入ったときの劣化」を測るためである。`matched`は同じ設定の`training_noise`だけを切り替えて、既知noise適応の診断対照として後から実行できる。
