## 結論

外側の別日分割は正しく動作している。学習は6/11・7/9の1,860秒から211秒を除いた1,649秒、評価は6/18の1,080秒すべてで、学習WAVと評価WAVの重複はない。データ読込が2回表示されたのは学習日が2日だからであり、二重読込の不具合ではない。

一方、当該runの`performance_kfold`は学習1秒を通常KFoldで分けたため、全3 inner foldで同じ29 WAVがfit/validationの両側に入った。外側テストの漏洩ではないが、未知WAV・未知日へ使う統合重みの推定としては過度に楽な検証である。内部ではCNN+Transformerを最良と判定して46.30%を与えたが、別日3 kHzでは同モデルがR²=-0.084となり、統合をRF単体より悪化させた。主設定は元WAV分離へ変更した。

3 kHz CNN+Transformerの失敗は全域の学習不能ではない。低熱流束を一貫して高く予測する別日バイアスが主で、高熱流束域のR²は0.821を保つ。300 epochの最終lossも約`5.88e-4`であり、epoch不足だけでは説明しにくい。学習日7/9の音響―熱流束対応が弱く、選別後の少数の中高熱流束秒が低熱流束域に近い入力強度を持つこと、3 kHzでは22 kHzより狭いスペクトル形状へ依存しやすいことと整合する。ただし、選別なしの同一300 epoch対照がないため、選別が悪化原因とはまだ確定しない。

## IG警告の判定

表示された`RuntimeWarning`は例外ではなく、4096点まで計算を続けた上で厳しい二条件の一方を満たさなかったという品質警告である。runは完了しており、診断JSONも保存されている。新しいGauss–Legendre実装`raw_straight_line_ig_gauss_legendre_v2`が使用され、旧64分割の破綻とは区別する。

- 3 kHz: 10 map中2 mapだけ総合収束。completeness残差の絶対値は69～1,406 W/m²、最終map変化は0.43～1.13%。
- 22 kHz: 10 map中5 mapが総合収束。残差は3～683 W/m²、map変化は0.35～0.82%。
- 判定基準はモデル出力差に対する0.1%+絶対`1e-6`、かつmap変化1%以下。わずかな未達も成功扱いにしていない。

したがって旧実装より桁違いに改善しているが、`converged=false`のmapは研究上の確定図として扱わない。結果を見て許容値を緩める修正は行わない。必要ならゼロbaselineではなく学習側の背景baselineを事前定義した別比較を行うが、これは説明する問い自体が変わるため別実験とする。

## 実装修正

1. 主設定の内部検証を`wav_kfold`へ変更。元WAV中央値のOOF R²で`performance_kfold`重みを計算し、同一WAV秒の共有を防ぐ。
2. 固定`peak_height`選別と`subset_equal_cv / crossfit_wav_stack / crossfit_shrinkage_stack`を併用可能にした。選別後データだけで、元WAV非重複の共通4-fold OOFを作る。
3. 主設定で新3方式を有効化し、3方式は同じinner OOFを共有。主図は正則化付き方式だが、実データでの優位性は未確認なので全方式を保存する。
4. `読み込みスタート`を、パス・件数・shape・目的変数範囲が分かるログへ変更。Kerasの予測プログレスを抑止し、内部学習でepoch表示を省略することを明記した。学習日の2連続読込を正常な2データ集合として識別できる。
5. 固定的なoutput/evaluation/explainabilityとモデルregistryを`code/utils/config/onb_defaults.py`へ移し、主configには実験ごとに変える条件を残した。解決後の全設定は従来どおりmanifestへ保存する。

## 次の識別比較

コード修正と性能改善を混同しない。まず3 kHz・無雑音・同じseed/300 epochs/全テスト秒で次を固定比較する。

1. 6/11+7/9学習の選別なし対選別あり。選別の純効果を判定する。
2. 6/11だけ学習対6/11+7/9学習。7/9追加による負の転移を判定する。
3. 新crossfit 3方式は同じ単体予測で比較し、最良単体、全域、ONB近傍、誤警報を分ける。
4. 上記で方向が決まってから複数seed。6/18を見て方式を選んだ結果は原因診断であり、最終的な一般化主張には新しい独立日が必要。

現在の主コードは150 epochsに設定されている。当該runはmanifest上300 epochsなので、厳密な再現比較時はepochを300へ明示して別runとして保存する。
