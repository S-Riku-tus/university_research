## 基準RMSと保存

**生成機能と比較条件の区別（本人質問への補足）**：ノイズを生成できるようにするだけなら、既存コードの`REFERENCE_SNR_DB`を変更するだけでよかった。`None`は無雑音も生成する指定で、既存ファイルを検出して省略する指定ではない。`[None, 0, -4, -8, -12, -16, -20]`なら無雑音と6雑音を同じ実行で作る。既存cleanを作り直さず残りだけ追加する場合は`None`を外す。

`REFERENCE_RMS_MANIFEST_PATHS`は生成機能の必須設定ではなく、AIが今回選んだ「旧日と同じ付加雑音のPCM振幅で比較する」条件の実装。各実験の代表RMSに対する相対的な負荷を比較する設計もあり、旧日基準の継承が一律に必須という意味ではない。現コードでは空リストで従来の対象全体の中央値推定へ戻せる。どちらの方式でもWAVごとに個別の雑音振幅を作る旧ショートカット方式へは戻らない。本補足ではコード・実行中の設定を変更していない。

旧6/11・6/18の保存manifestを読み、共通の`0.0004822199855309985`を使う。新日の音の強さから雑音強度を再定義しない。2参照のRMS不一致、非正/非有限値、高域通過条件の不一致では生成前に停止する。参照パスとSHA-256を新しい生成記録へ保存する。

元のband直下の`preprocess_manifest.json`と`global_reference_manifest.json`は保持する。追加条件は各`heatflux_reference_SNR=.../preprocess_manifest.json`へ記録し、継承基準は`global_reference_manifest_noise.json`へ別保存する。追加ノイズの設定を確認するときは条件別のmanifestを参照する。旧root manifestのclean設定を追加ノイズの設定へ流用しない。

同じsource/chunkではSNR間で同じ水流音区間を使い、振幅だけ変える。source間のshared seedも保持。Windowsの長いNPY/PNG/CSVパスへの保存と、chunk manifestの追記も確認した。
