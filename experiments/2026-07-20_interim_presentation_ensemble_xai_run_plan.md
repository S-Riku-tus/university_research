# 中間発表向け ONB・アンサンブル・XAI 実行計画

## 1. 今回の目的

今回の実行では、次の二つを分けて検証する。

1. 個別モデルよりアンサンブルが高性能か。
2. 個別モデルが異なる時間・周波数領域や異なるサンプルを得意としており、その相補性がアンサンブルの改善と整合するか。

「XAI が異なる」だけでは性能向上の原因とは断定しない。説明性指標、モデル間の誤差の違い、実際にアンサンブルで誤差が減ったサンプルの三つが対応した場合に、「異なる特徴利用による相補性が改善要因である可能性が示された」と述べる。

## 2. 7/17 結果から分かっていること

`20260717_fixed_ensemble` の保存名に対し、実際の run tag は `vleg` であり、外側の検証 fold の正解値から重みを決める `val_fold_legacy` が使われていた。この方式は評価情報のリークを含むため、中間発表での最終的な性能向上根拠には使わない。

3実験 × 2周波数 × 2ノイズ条件の12条件を再集計すると、7/17のアンサンブルが最良の個別モデルを上回った条件数は、R² が1/12、ONB RMSEが1/12、Recallが0/12、F1が0/12だった。したがって、現時点で「アンサンブルにより個別性能を上回った」とは言えない。今回の実行は、この結論を隠さず、リークのない共通条件で重み候補を比較し直すものとする。

7/17の保存済みfold予測を学習なしで固定重みに再合成した事前診断でも、RF98/1/1はR²改善が4/12、平均差が -0.000119、Recall改善が0/12だった。一方、3モデルの予測最大値はR²が0/12で平均 -0.05095と悪化したが、ONB RMSEは9/12で改善し、RecallとF1は各3/12でごく小さく改善した。このため、固定平均は全体回帰の主比較、予測最大値はONB見逃しとのトレードオフを調べる探索的比較として扱う。

## 3. 今回の実行条件

- 実験: 3条件
- 周波数上限: 3 kHz、22 kHz
- ノイズ: no noise、SNR -20 dB
- 評価: 5-fold、500 epoch
- 個別モデル: RF、CNN+Transformer v2 GAP、AlexNet
- 主比較アンサンブル: RF 0.98、CNN+Transformer 0.01、AlexNet 0.01
- 同時比較: 等重み、RF90/5/5、RF95/2.5/2.5、RF98/1/1、RF95/CNN-Tf5、RF95/Alex5、予測最大値
- XAI: 22 kHz の no noise と SNR -20 dB、fold 1

固定重み、等重み、予測最大値は、各 fold で一度だけ学習した同一の個別モデル予測から全候補を計算する。そのため、候補を増やしても学習回数は増えない。予測最大値はONBの見逃し回復を狙う探索的な後段統合であり、R²を犠牲にする可能性がある。`inner_holdout` は実装済みだが、個別モデルを内側と外側で学習し直して実行時間が概ね増えるため、今回の既定値では無効にしている。

## 4. 実行方法

リポジトリ直下で次を実行する。

```powershell
python code/run_ensemble_regression_onb.py
```

本実行前に短い動作確認を行う場合は、`VALIDATION_CONFIG["run"]["smoke_test"]` を一時的に `True` にする。本結果では必ず `False` に戻す。

## 5. 実行後に最初に見る出力

各 run フォルダの主な出力は次の通り。

- `bar/ensemble_improvement_<noise>.png`: 最良個別モデルに対する各戦略の改善量。正が改善、負が悪化。
- `ensemble_strategy_comparison_<noise>.csv`: 全指標について、最良個別モデル、差分、paired SE、改善したfold数を保存。
- `ensemble_correction_summary_<noise>.csv`: RFより誤差が減った・増えたサンプル数、ONB近傍の誤差差、false negativeの回復数と新規発生数。
- `model_diversity_<noise>.csv`: 個別モデル間の予測相関、残差相関、サンプルごとの勝敗。
- `fold_pred/pred_f<fold>_<noise>.csv`: 全個別モデルと全アンサンブル候補の予測。追加解析の根拠データ。
- `explainability/model_group_mask_comparison.csv`: モデル別・時間帯別・周波数帯別のマスク性能低下と順位。
- `explainability/top_groups_by_model.csv`: R²、ONB RMSE、Recallに最も影響した時間帯・周波数帯の要約。
- `explainability/group_mask_comparison_<axis>_<metric>.png`: 3モデルの重要時間帯・周波数帯を同一スケールで比較する大文字版ヒートマップ。

従来型のR²/AUC棒グラフは、文字の密集を避けるため、3個別モデルと事前指定した主アンサンブルだけを表示する。全重み候補の比較には専用の改善量グラフを使う。

## 6. 発表での判定ルール

### A. アンサンブルが明確に改善した場合

- R²だけでなく、ONB RMSEまたはRecall/F1でも改善している条件を示す。
- 12条件中の改善条件数と平均改善量を併記する。
- RFのfalse negativeを何件回復し、何件新たに発生させたかを示す。
- 事前指定した主戦略が改善した結果を主に扱い、結果を見て選んだ最良戦略は探索結果として区別する。

### B. R²のみ改善し、ONB検知が悪化した場合

「回帰全体ではわずかに改善したが、研究目的で重要なONB検知とのトレードオフが残った」と報告する。「性能が向上した」と一括して表現しない。

### C. 個別モデルを上回らない場合

「単純な予測平均では強いRFを薄めた。異種モデルを入れるだけでは改善せず、ONBを目的にした重み学習または補正モデルが必要」と結論づける。この結果も、アンサンブル成立条件を明らかにした進捗として発表できる。

## 7. XAI と性能改善を結ぶ条件

次が同時に確認できた場合のみ、相補性の説明へ進む。

1. `top_groups_by_model.csv` で重要な周波数帯・時間帯がモデル間で異なる。
2. `model_diversity_<noise>.csv` で残差相関が十分に低く、RF以外が勝つサンプルも存在する。
3. `ensemble_correction_summary_<noise>.csv` で実際にRFの誤差やfalse negativeが減る。

ヒートマップは内部配列 `(time, frequency)` を計算時には維持し、表示時だけ転置して、横軸を時間、縦軸を周波数に統一している。入力スペクトログラムとの比較はこの表示方向で行う。RFのTreeSHAPはPCA成分の説明なので、物理的な周波数帯の比較には使わず、全モデル共通の grouped masking を使う。

## 8. 中間発表での安全な結論形

現段階の第一候補は次の形である。

> 7/17の方式には重み決定時の評価情報リークがあり、かつONB指標の改善も確認できなかった。そこで、同一の個別モデル予測に対してリークのない複数の固定重みを比較し、全体回帰とONB検知を分けて再評価した。さらに、共通の時間・周波数マスク指標と誤差相関、アンサンブルによる誤り訂正を対応づけ、モデル間の相補性を検証した。

新しい結果が改善を示した場合だけ、この末尾に「その結果、〜条件で最良個別モデルを上回った」を追加する。
