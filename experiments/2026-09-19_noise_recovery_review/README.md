# 現行データのノイズ曲線が谷型になる理由を絞る（保存予測の追加監査）

記録日：2026-09-19。対象は[9/18完了run 151715](../2026-09-18_onb_full_sweep_151715/README.md)のみ。学習6/11、評価6/18の18 WAV・全1080秒、22 kHz、各SNRに合わせた**matched再学習**、seed 42、200 epochs、元WAV分離、学習986秒・テスト無選別。参照SNRは無雑音、0、−4、−8、−12、−16、−20 dB。現在編集中の主コードの実験日設定や、別runをこの結果に混ぜない。

## 再計算した確認事実

[再計算スクリプト](analyze_saved_predictions.py)で7条件の`fold_pred`を読み、`experiment_name, source_wav_id, chunk_index`の1080キーと熱流束ラベルが完全に一致することを検査。各条件のR²を同じ全1080秒で再計算した。[全7条件・5方式の値](r2_from_saved_predictions.csv)、[対応するWAV別二乗誤差差](paired_wav_sse_changes.csv)。等重みは保存された3単体予測の算術平均として**事後計算**したもので、新しい重み学習や独立検証ではない。

| 22 kHzのR² | 無雑音 | −8 dB | −16 dB | −20 dB |
|---|---:|---:|---:|---:|
| RF | .8501 | .8599 | .8587 | .8560 |
| CNN＋Transformer（結果表示名Conformer） | .8986 | .7862 | .8990 | .8127 |
| AlexNet | .8910 | .8108 | .8051 | .9036 |
| 現行`inner_holdout`統合 | .9112 | .8261 | .8838 | .8756 |
| 保存予測の等重み平均 | .9143 | .8373 | .8697 | .8751 |

−8→−16の統合R²改善は+.0577、CNN＋Transformerの改善は+.1128。−8→−20の等重みでも+.0378改善している。したがって**現行統合重みだけでは谷型を説明できない**。等重みは無雑音と−8で現行重みを上回るが、−16では下回る。重みの改善余地と、単体学習・入力側の問題は別に扱う。

同じ1080秒の予測から、−8→−16の統合二乗誤差減少は約**4.62×10^9 (W/m²)²**で、18 WAV中10本が改善、8本が悪化。CNN＋Transformerでは約**9.03×10^9 (W/m²)²**、13本改善・5本悪化。−8→−20の統合は約**3.97×10^9 (W/m²)²**だが、改善は8本、悪化は10本。全体の持ち直しは「全WAVで良くなった」という意味ではない。統合−8→−16の二乗誤差減少はONB前が約3.00×10^9、ONB以上が約1.62×10^9 (W/m²)²で、ONB前だけに限定されない。WAVは同じ18本で、1080秒を独立反復とは数えない。

## 何が原因と判明し、何が未確定か

1. **曲線の意味は確定**：`noise_trends`は各SNRの**別々に学習したモデル**の指標を集める。[作図コード](../../code/utils/plotting/noise_trend_plots.py)は同じ実験・run hash・評価定義の曲線へ結ぶが、matchedで**学習済み重みの同一性は要求しない**。したがって曲線は「ノイズだけを増やした固定モデルの応答」ではない。強ノイズでR²が高いことから水流音が物理情報を増やしたとは言えない。
2. **旧ノイズ振幅shortcutは現行runの主因と認定できない**：[2026-08-17生成版の条件記録](../../configs/datasets/waterflow_20260817_1s.yaml)は`fixed_global_rms`、全49 WAVの中央値から固定した基準RMS、SNR間で同じノイズ区間を使用。ノイズ倍率は元WAVごとのRMS・熱流束ラベルで決めない。旧相対RMS版についての[8/17原因確定記録](../../docs/research_plan/2026-08-17_noise_accuracy_reversal_investigation.md)を現行の説明に流用しない。9/15解析は216配列の再構成も照合済み。
3. **ノイズの実際の強さは周波数と録音ごとに違う**：フォルダのSNRは全体の固定基準。2–3 kHz帯は−20 dB参照条件でも既存の54区間で帯域内SNR中央値+4.05 dBで、他帯域は負。[9/15帯域診断](../2026-09-15_onb_frequency_comparison/analysis.md)。RFが比較的横ばいでCNNが条件別に大きく変わることと整合するが、谷型の**原因を単独で証明しない**。
   同じ時間窓の複素STFTを`S`（付加前音）、`N`（水流音）、振幅倍率を`a`とすると、入力powerは`|S+aN|² = |S|² + a²|N|² + 2a Re(S N*)`。最後の交差項は符号が変わり得るため、**雑音振幅を単調に増やしても個々の周波数画素のpowerや形は単調とは限らない**。現行のlog圧縮・resizeはさらに特徴の見え方を変える。これは機構上の可能性で、今回の回復を交差項が生んだと実測で確定したわけではない。
   同じ水流音源と、chunk番号に対応するノイズ区間を元WAV間・SNR間で共有する生成設定も確認した。複数の日付組み合わせで似た形が出る場合、共通の入力処理・雑音音源・帯域依存が候補になる。一方、同じ水流音源を共有した曲線の反復を、独立した雑音実験と数えない。別のノイズ区間・独立録音で形が再現するかが次の識別点。
4. **有限データ・学習変動・日差・入力表現・重み転送は未分離**：9/18runは1つの学習日・評価日・seedで、同じ名目条件の別runでもCNN値が変化した。[9/18run](../2026-09-18_onb_full_sweep_151715/README.md)はその原因を確定していない。ノイズ条件ごとの再学習、224×224へのresize、log-power、別日差が混ざる。−8で統合がRFより低い点には重みの偏りが関係し得るが、保存予測だけから因果割合は決められない。
5. **「必ず単調低下」は必要な合格条件ではない**：現行の水流音は周波数依存で、各SNRの学習済みモデルも異なる。clean_onlyでも有限標本のR²は必ず単調になるとは限らない。原因が未確定のまま曲線を単調に整える処理はしない。

**学習lossの確認**：同runの`maxfreq=22kHz/heatflux_reference_SNR=-8/loss/loss_conformer_f1_-8.png`と、`...=-16/loss/loss_conformer_f1_-16.png`を目視確認した。いずれも終盤の**training lossが低く、おおむね平坦**に見える。−8 dBの低精度を「200 epochsで学習lossが全く下がらなかった」とは説明できない。[学習コード](../../code/utils/training/model_training.py)は`validation_data`・早期停止を指定せず、[図の実装](../../code/utils/plotting/regression_plots.py)もtraining lossだけを描く。**過学習か、最良epochはこの出力から判定不能**。診断するなら学習日の元WAVを分離した内部検証を追加し、評価日6/18をepoch選択に使わない。

## 原因を確定するための最短の識別比較

| 順序 | 一つだけ変える内容 | 結果ごとの解釈と次の対処 |
|---|---|---|
| A | 保存予測で、谷と回復の標本別二乗誤差・バイアス・重み・等重みを確認する（本監査で開始） | 一部WAVへ集中ならその録音の振幅・帯域・ラベル対応・日差を確認。現行重みだけが悪ければ学習側重みの安定化を試す |
| B | 同じ学習済みcleanモデル・PCA・scaler・統合重みを固定し、同じ評価WAVをSNRだけ変えて予測する`clean_only` | 谷が消えれば**SNR別再学習や重みの変動**が主要候補。残れば固定モデルに対する入力／前処理の非線形応答や標本構成へ焦点を移す。消えたことだけでどの学習要因かは確定しない |
| C | 代表SNR・同じ分割で複数seed、同じ学習予算と学習曲線を比較 | 谷の大きさがseed変動内なら不安定性として報告。seedを越えて残るならデータ・表現・日差の候補を優先。現行はtraining lossのみなので、必要なら学習日内で元WAVを分けたvalidationを新設 |
| D | 同じ録音・同じ雑音区間で、共通Hz格子の帯域別SNRと予測変化を照合。必要なら同幅帯域の保持／除去、背景値置換、再学習 | 変化が特定帯域と一貫して対応すれば入力依存を支持。マスクだけで物理原因を決めない。ノイズだけの入力対照は、ノイズ区間がラベルと無関係か確認する用途に限定 |
| E | 設定を固定して独立日・独立水流音で評価する | 曲線が変われば日／ノイズ源への依存を結論に含める。改善が再現する場合も回帰・ONB別に扱う |

診断の順序は[発表後の計画](../../docs/research_plan/2026-09-19_research_actions.md)と矛盾しない。ただしノイズ曲線の機構を直接切り分けるには、選別のA/B比較より**Bの固定モデル対照**が情報量の大きい実験である。選別A/Bは選別効果という別の問いとして、基準条件を固定して進める。

## 結果に応じた対処

- **seed・学習順が支配的**：乱数の設定と実行順を監査し、代表条件を反復する。学習日内の検証でepochと学習予算を決めて固定し、差が反復変動内なら単一曲線から優位を主張しない。
- **内部では良い単体へ重みが偏り、別日では順位が逆転**：既存予測で等重みを対照にし、重みを学習側の元WAV分離予測だけで安定化する。0.9143など事後等重みの数字をそのまま方式選択の根拠にしない。次の独立日で採用効果を評価する。
- **特定の帯域・雑音音源でのみ谷が残る**：実現帯域SNRと入力差を照合し、共通Hz幅の入力保持／除去、別水流音源で確かめる。周波数上限を変えるとresizeも変わるので、その交絡を固定する。物理的に不要な帯域の除去が独立評価でも有益と確認できた場合に限り採用する。
- **実験日で校正ずれがある**：日別・熱流束別の残差を示し、学習日側だけで行える校正や追加日学習を対照比較する。テスト日を使った閾値・重み補正を同じテスト日の性能改善として報告しない。
- **固定モデルでも非単調が残るが、独立日・独立雑音では再現しない**：現行生成音源とデータの適用範囲を明記する。単調な曲線にするためだけの処理は採用しない。

現行主コードの作業ツリーには実験日を変更した未コミット編集があるため、上記の完了runの設定と混同しない。この監査では主コードも原runも変更していない。
