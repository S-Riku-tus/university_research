# 1秒スペクトルの「ピークの高さ」で学習区間を選ぶ

2026-09-16。本人の付録図と追加説明を受け、先行実装の「2–3 kHz帯域パワー・ONB前99パーセンタイル」を、**特定周波数付近のピークの高さに横線を引く方法**へ変更した。学習6/11・7/9、テスト6/18、内部の通常chunk KFold、性能重みアンサンブルは継続する。

最初に [スペクトルと閾値を動かす画面](peak_threshold_review.html) をブラウザで開く。実験日・60秒の録音・秒を選べる。横線の高さを0.3、1、3、10に変えると、その高さで残る秒と各秒のスペクトルを確認できる。画面操作は確認用で、主コードのconfigを書き換えない。

## 1. 説明を訂正する

前の99パーセンタイルは、「ONB前の帯域パワーを小さい順に並べたとき、99%がそれ以下となる強さ」を基準にするものだった。これは本人の意図した「1,000・1,500・2,300 Hz付近の山の高さを見て、弱い前後をどこまで含めるか」と異なる。ONB前に既に大きい山がある録音もあり、そこを一括して背景と呼ぶ問題もあった。

今回は1秒ごとに、**2,300 Hz付近の山の一番高いところ**を読む。その高さが横線以上なら採用する。横線を下げれば弱い山も入り、上げれば強い山だけになる。周波数の2,300 Hzは「見る場所」で、採否の閾値は**縦軸の高さ**である。

山の位置が少し動くため、2,300 Hzちょうど1点でなく、**2,100～2,500 Hzの最大値**を読む。帯域内の面積は足し合わせない。秒ごとの最大値を1にする正規化も行わない。

## 2. 付録図と現在のスペクトルの対応

- 本人提示の図は付録Fig. E.0.1。保存済み[卒論抽出テキスト](../2026-09-15_onb_frequency_comparison/thesis_extracted_text.txt)の本文にも、Experiment 1・0.2607 MW/m²と1,100・1,400・2,200 Hz付近の山の記載がある。
- 旧 `Spectrum.py` はWAV全体を扱い、正規化も含む。より近い処理は [spectrum_任意の秒刻みで表示.py](../../archive/code/trush_box/spectrum_任意の秒刻みで表示.py) にある。ただしこのファイルはHann窓付きFFTの二乗を使い、`chunk_samples=4410`、44.1 kHzなら**0.1秒**となる。ファイル名やコメントだけで「添付図も1秒」と確定できない。添付図を作った実行版・パラメータの完全一致も未確認。
- 新しい全画像は、現行の1秒chunkに対応する**線形Welch PSD**を用いる。44.1 kHz、Hann 2,048点、重なり1,024点、定数detrend、周波数間隔約21.53 Hz。500 Hz高域通過後・付加ノイズ前の音で計算した既存PSDを再利用し、元WAVとのパワー照合は[前回の監査](../2026-09-16_day_split_spectral_selection/spectrum_manifest.json)で全秒実施済み。
- PSDは周波数ごとの強さの尺度で、ここではデジタル振幅²/Hz。マイクの音圧校正をしたPa²/Hzではない。図の表示を見やすくするため**縦軸を10⁹倍**している。図の高さ「1」はconfigの`1e-9`に対応する。
- 録音ゲインや計測感度が変われば、同じデジタル値が同じ物理的な強さとは限らない。今回の共通線を他の収録条件にも使えると確定したわけではない。
- 旧FFT二乗とWelch PSDでは窓長・平均化・尺度が違う。そのため、**付録の縦軸0.1や1.6を今回の閾値へ直接移せない**。同じ計算法・固定した尺度で、強い秒と弱い秒を比較することを優先した。PSDの尺度は[SciPy公式Welch仕様](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.welch.html)にも対応する。

Welchは1秒内をさらに短い窓で平均する。その秒内に短く出た大きな音も「1秒としての強さ」へ平均される。秒未満の発生時刻を決定する処理ではない。

## 3. 3つの山を確認し、2,300 Hz付近を先に使う理由

全2,940秒について、850–1,200 Hz、1,250–1,650 Hz、2,100–2,500 Hzの高さと山の位置を保存した。近傍幅は今回の録音で位置がずれることを許容する範囲であり、物理的に唯一の範囲と主張しない。各WAVの[60秒時系列](timelines/)には3本の高さを重ねている。

7/9の代表録音では、2,300 Hz付近の山が弱く残る秒に、1,000・1,500 Hz付近は背景に近くなる例がある。[同じ縦軸での4秒の比較](example_spectra.png)を参照。3つ全部が同時に高いという条件にすると、本人が含めたい弱い部分まで除く可能性があるため、現段階は2,300 Hz付近を単独の候補にする。3帯域を比べた識別精度を確認して「最良帯域」と決めたわけではない。

高さだけの条件は、同じ帯域の外来音や広い盛り上がりでも通過する。現段階では「沸騰らしいピークを含む学習候補」のルールであり、気泡の存在を保証する検出器ではない。付加する水流音で採否が変わらないよう、選別は必ず付加前のclean音で決める。

## 4. 横線をどこに置くか

図の表示単位（×10⁻⁹）で、**暫定値を1**に設定した。日別の分位点へ自動追従させず、同じ横線を使う。

判断の根拠は学習日の音である。熱流束がONBの半分未満の領域では、2,300 Hz付近の最大高さは6/11で0.052、7/9で0.328だった。一方、7/9の明瞭な山は10を超え、その間に1～10程度の弱い山がある。1はこの低熱流束の参照領域より高く、弱い山も一部含める候補である。これは「背景最大値の3倍」という自動推定式ではなく、図で比較するための固定値を選んだ説明である。

ONB前の全秒を背景とすることは避ける。例えば6/11のONB直前には35.65まで大きくなる秒がある。これを理由に横線を35以上へ上げると、今回含めたい弱い山を落としてしまう。低熱流束の参照領域も、秒単位の気泡なし正解が確認された集合ではない。

**7/9・643.52 kW/m²の60秒での比較：**

| 横線の高さ | 残る秒数 | この録音での含め方 |
|---|---:|---|
| 10 | 5/60 | 強い山を中心に残す |
| 3 | 9/60 | その周囲の比較的大きな山も残す |
| **1（暫定）** | **13/60** | より弱い山まで含める |
| 0.3 | 16/60 | 0.5程度の小さい山も含める |

具体的には、2～3秒は116.534、4～5秒は3.456、9～10秒は0.513、11～12秒は0.035。横線1なら前2つを含み、後2つを除く。0.3へ下げれば9～10秒も含む。[例の画像](example_spectra.png)、[60秒全体](timelines/2025.07.09_0.3_1_index=14.643516.png)。

ここで10を「強い」と呼ぶのは説明上の区分で、正解や第2の学習条件ではない。実際の採否は横線1だけで決まる。強い秒の隣だから自動的に採用する処理はなく、隣接秒もその秒自身の高さで判断する。1秒列は必ず滑らかに増減するわけではなく、孤立した山もある。

同じ設定を学習2日に適用した残存数は、0.3なら1,652秒、1なら1,649秒、3なら1,641秒、10なら1,633秒。[全候補・全WAV](threshold_sensitivity.csv)、[学習全体](training_threshold_counts.csv)、[帯域別・領域別の数値](peak_height_regions.csv)。

**1が物理的・予測性能上の最適値と判定できたわけではない。** 現時点で秒単位の気泡イベント正解がないため、「どこまでを沸騰音と認めるか」の唯一の境界は決まらない。主比較では1を固定し、必要な感度確認を0.3・3で行う。テスト6/18の予測精度で横線を選び直さない。6/18の図も依頼どおり出力・記述しているため、完全な未閲覧データとは呼ばない。

## 5. 学習への適用

1. 元WAV・秒番号でcleanのピーク高さを対応付ける。
2. **ONB未満の熱流束は従来どおり保持する。** ONB以上の学習秒にだけ、高さ以上という条件を適用する。熱流束ラベルを変えない。
3. 内部KFoldのfit側だけを選別し、validation側は全秒で予測する。3-foldを通して1,860秒を一度ずつ検証し、その単体性能で統合重みを決める。
4. 学習2日の選別後集合で最終学習する。最終テスト6/18は**全1,080秒・18 WAV**を評価する。
5. 同じ元秒なら周波数上限・ノイズ条件が違っても同じ採否とする。現行105 manifest全てで一致を検算した。

| 実験日 | 元の秒数 | 学習に残す秒数 | 扱い |
|---|---:|---:|---|
| 6/11 | 1,080 | 1,080 | ONB以上は全480秒が高さ1以上 |
| 7/9 | 780 | 569 | ONB未満360秒を保持、ONB以上209秒を採用 |
| 6/18 | 1,080 | 対象外 | テストとして1,080秒全て評価 |

7/9では442.17・505.10 kW/m²は各0/60、571.69は16/60、643.52は13/60、720.69以降の3 WAVは各60/60となる。最初の2点の特徴が弱い事実は残るが、これを「沸騰していなかった」と断定しない。実験上のONB、録音の対応、計測感度との関係は引き続き確認対象である。

旧ルールの1,648秒と新ルールの1,649秒は、単に1秒追加した関係ではない。6/11で8秒を復帰し、7/9で7秒を新たに除外した。[検算記録](verification.json)。選別で不足する領域への補正は本人指定により今回追加していない。

## 6. 設定・再現方法

実行設定は [ONB主コード](../../code/run_ensemble_regression_onb.py) の `VALIDATION_CONFIG["acoustic_selection"]`。

```python
"mode": "peak_height",
"feature": "peak_2100_2500_psd",
"peak_height_threshold": 1.0e-9,  # 図の横線 1。0.3なら0.3e-9、3なら3e-9
"peak_height_threshold_by_experiment": {},
```

同じCSVには `peak_850_1200_psd` と `peak_1250_1650_psd` もある。別の山へ切り替える場合はfeatureと、その山を見て決めた高さを一緒に指定する。同じ数値がどの山にも最適とは限らない。日別上書きは明示指定時のみ使う。ピークの計算法・単位が異なるCSVはエラーにする。

- 数値特徴・全画像・時系列・HTMLの再生成：`python code/review_boiling_peak_heights.py`
- 画像以外の再生成：同コマンドに `--skip-images`。既存画像の削除・置換はしない。
- 自動テスト：`python -m unittest discover -s tests -v`
- 新ルールの実データ動作確認：`python code/verify_day_split_pipeline.py --output-tag 20260916_peak_height_smoke --selection selected`
- 全画像・特徴・manifest・実行結果の検算：`python code/audit_peak_height_outputs.py`

各実験の全画像は `data/spectrum_peak_png/waterflow_20260817_1s/<WAV名>/chunk-0000.png` から `chunk-0059.png`。左は録音内で縦軸を固定した全高表示、右は全録音共通で縦軸12までの拡大表示。大きい山が拡大図では切れることを明記している。旧dB画像・元WAV・NPYは保持した。
