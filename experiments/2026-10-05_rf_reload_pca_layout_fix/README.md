# RandomForest保存再読込時のPCA数値差を修正

確認日: 2026-10-05。本人実行の`183837` runが、最終RFの保存再読込検証で停止した。報告値は最大11960.8984、平均1495.1123 W/m²。[対象条件](../../configs/experiments/2026-10-05_rf_reload_pca_layout_fix.json)、[実データ確認](verification.json)。

## 確認事実

- 停止runには内部3モデルOOF、最終RF・PCA・scalerが残っている。外側予測や完了印はなく、最終CNN系の学習前に停止している。新しい外側精度・q100は未取得。
- 保存PCAの成分値を一切変えず、randomized PCAの非連続Fortran viewと再読込後のC配置を作り、同じ学習側8 chunkへ適用した。丸め後のPCA特徴が1セルだけ8e-6/9e-6へ分かれ、RF出力の最大11960.8984375、平均1495.1123046875 W/m²差を再現した。
- 木の閾値をまたぐため、微小なPCA計算差が大きな出力差になる。6桁の丸めだけでは、丸め境界をまたぐ場合を防げていなかった。以前の小型テストはこのPCA配置を覆っていなかった。

## 修正と確認

- [共通PCA変換](../../code/utils/training/model_training.py)で、成分とmeanをC連続配置へ統一してから同じ6桁丸めを行う。成分値・dtype・PCA100・データ分割・モデル採用値は維持。学習・評価・説明性が同じ変換を使う。
- 実行snapshotと学習状態manifestへ`pca_transform_version=2`を記録。主実行の条件hashも変わるので、修正前の実行を修正後の完了結果として再利用しない。
- 再読込検証の許容値と有効設定は維持。停止runの保存RFを使い、同じ8 chunkで実際の`save_and_verify_model()`を通したところ最大・平均差とも0 W/m²で通過した。元の3保存物のSHA-256は変更前後で一致し、停止runを上書きしていない。
- 非連続PCA成分をjoblib保存する回帰テストを追加。修正前は1/160セルの不一致で失敗、修正後は一致。関連49テスト通過。[テスト記録](tests.json)。研究モデルの本学習は再起動していない。

主コードはclean_only・chunk内部3-fold・保存/再読込確認ありのまま。同じ主コードを通常どおり再実行する。保存途中からのモデル学習再開機能を追加した変更ではない。

この修正では丸め境界付近の特徴が旧計算と変わり得る。次の新旧比較には内部分割変更と数値互換性修正の両方が含まれるので、単体予測と重みの変化を分けて読み、差を分割だけの因果効果とは断定しない。
