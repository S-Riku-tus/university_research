2026-10-06。本人の最新指示は、従来のRF・Conformer・AlexNetを固定し、その上にHGBや他候補を追加して改善を検証すること。「14つ」は文脈から4つと解釈した。前回の[RFを外す採用判断](../2026-10-06_model_adoption_decision/README.md)は主方針として更新し、元3を保持する。

**9候補方針のnested学習と4・5モデル統合を完了した。clean OOFで第5候補に選ばれたのは両seedともExtraTrees。元3＋HGB＋ExtraTreesの5モデルは、元3に対してclean回帰・見逃しと強雑音RMSEを両分割で改善し、全7条件でFP0だった。** ただし元3＋ExtraTreesの4モデルとの差は小さく、HGBだけを加える4モデルのq100利得を失う場合もある。「5つならすべて良くなる」という結果ではない。

## 1. 今回、何を固定して何を追加したか

| 項目 | 実施した条件 |
|---|---|
| 元3モデル | 保存済みseed43/44のXGBRF・Conformer・AlexNet。学習値・構造・予測を一切再fitしない |
| 基準HGB | 保存済み周波数34、leaf31/最小leaf20/L2=1。予測を変更しない |
| 録音・入力 | 2025/6/11＋6/18、各18段階、36 WAV。3 kHz、1秒、224×224、選別なし |
| 外側 | 保存済み分割、各WAV45学習/15評価、1620/540。同じ評価chunkで追加なし/ありを比較 |
| 内部OOF | 保存済みchunk KFold3、shuffle=True、seed43/44。fit1080/held540 |
| 候補選択 | 各fit内でさらに3-fold chunk CV。前処理・ラベルscaler・PLS・設定選択はfit内のみ |
| 最終候補fit | 外側学習1620の内部CVで選び、1620へ再fit。外側540は選択に渡さない |
| 学習方針 | 候補も統合もclean_only。全モデルを同じ6雑音へ固定転送 |
| 追加候補 | HGB正則化、ExtraTrees、RF34、通常GB、XGBoost、直接Ridge、PLS、Kernel Ridge、時間46 HGB |
| 新学習量 | 648 fit（設定選択576＋保存72）。9方針×4ステージ×2seedの保存モデル72 |
| 統合 | seedごとに87方式、全7条件。3654指標行、元3・候補単体・4/5等平均・固定配分・制約付き重みを保存 |

元3のperformance重みを固定する主対照と、元3だけにMSE重みをfitして保存した比率を固定する公平な対照を使う。今回の「固定」は元モデルと元3内の比率を維持する意味。追加時には、元3全体と追加モデルの配分を変える。

元3ブロック25%以上・追加各5%以上を設計制約とした。4構成でRFを0にする前回の無制約MSEと区別し、5構成は全5つが正の重みを持つ。25%/5%は外側で選んだ最適値ではなく、今回の保持条件。固定4=75/25、固定5=50/25/25、4/5等平均も対照として取得した。

第5候補は9候補のclean OOF統合fit MSEで決めた。OOFの基礎予測は候補設定の選択もnestedだが、統合fitの指標自体は未使用メタ評価とは呼ばない。採用判断に使う外側結果も、同じ既存データを反復利用した開発判断であり、未知日や新データの独立検証ではない。

## 2. 元3に追加した4・5モデルの対応結果

以下は元3 clean-MSE比率を固定した比較。すべて同じ外側540、陽性315/陰性225、単位kW/m²。

| seed | 構成 | clean RMSE | MAE | FN / FP | −20 RMSE | −20 FN / FP |
|---|---|---:|---:|---|---:|---|
| 43 | 元3 | 35.74 | 26.70 | 32 / 0 | 81.41 | 62 / 0 |
| 43 | 元3＋HGB（4） | 26.10 | 18.77 | 25 / 0 | 93.01 | 53 / 0 |
| 43 | 元3＋ExtraTrees（4） | 24.74 | 17.28 | 26 / 0 | 75.35 | 49 / 0 |
| 43 | 元3＋HGB＋ExtraTrees（5） | **24.67** | **17.24** | **25 / 0** | **76.31** | **48 / 0** |
| 44 | 元3 | 33.89 | 24.12 | 28 / 0 | 81.41 | 63 / 0 |
| 44 | 元3＋HGB（4） | 26.48 | 18.69 | 22 / 0 | 74.09 | 58 / 0 |
| 44 | 元3＋ExtraTrees（4） | 25.37 | 17.03 | 20 / 0 | 73.84 | 58 / 0 |
| 44 | 元3＋HGB＋ExtraTrees（5） | **25.26** | **17.16** | **19 / 0** | **73.57** | **58 / 0** |

5モデルのRecallは92.06%/93.97%、R²は0.99166/0.99126。元3に対しcleanで27/36・28/36 WAVのMSEが改善。6雑音平均RMSEは69.39→65.63／67.49→63.41。5モデルは両seedの全7条件で観測FP0だった。[比較図PNG](fixed_three_comparison.png)、[PDF](fixed_three_comparison.pdf)、[WAV対応差](wav_errors.csv)、[誤り訂正/追加](paired_deltas.csv)。

元3の従来performance内部比率をそのまま保っても利得は残る。元3→HGB4→HGB＋ExtraTrees5のclean RMSEはseed43が36.04→26.46→25.05、seed44が35.30→26.99→25.74。FNは36→27→28、39→23→25。5は元3より良いが、HGB4より見逃しが2例増えるseed44もある。−20 RMSEは84.19→95.71→77.11、85.08→74.47→73.93。モデル追加と元3の重み変更の効果を混同しない。

**等平均との違い**：4等平均のclean RMSE33.70/34.09、5等平均30.68/31.01、5等平均FN38/38。同じモデル数でも学習側で配分を決める方式と同じ利得にはならなかった。固定配分の全結果も[指標CSV](metrics.csv)へ保存した。

## 3. RFとHGBのどちらが良いか

**現在のPCA画像RFより周波数HGBの単体は良いが、その差を学習器だけの優劣へ広げない。** 今回は同じ周波数34特徴のRF（XGBRF）も学習した。

| 単体 | clean RMSE 43 / 44 | −20 RMSE 43 / 44 | −20 FP 43 / 44 |
|---|---|---|---|
| 元RF・PCA画像 | 70.97 / 69.60 | 151.65 / 146.26 | 199 / 225 |
| RF・同じ周波数34 | 29.93 / 29.97 | 73.17 / 76.50 | 0 / 0 |
| HGB・周波数34 | 28.33 / 28.88 | 106.37 / 72.41 | 88 / 0 |
| ExtraTrees・周波数34 | **25.76 / 26.68** | 74.72 / 73.28 | 0 / 0 |

RF34は元RFに近い木数/標本・特徴抽出を持つ限定2depth比較で、すべてdepth12を選んだ。画像PCAから34特徴への変更でRFの性能が大きく変わることを確認した。一方、設定選択とPCA有無も含むので「34特徴だけが唯一の原因」とはしない。同じ34特徴でもcleanはHGBの方が少し良く、−20の順位はseedで変わる。HGBがRF一般より強いという結論ではない。

学習側で選ばれたExtraTreesはすべて最小leaf2・max_features1、256木。元3共通clean FN21/19の6/7例を単体で訂正し、単体FP0。HGBは7/6例を訂正した。両者のclean残差相関は0.849/0.863で、まったく独立な誤りではないが一致もしていない。[補完診断](error_complementarity.csv)。

## 5. 5モデルの利点と残る代償

### 実際の重みと、RFを保持する意味

| seed | RF | Conformer | AlexNet | HGB | ExtraTrees |
|---|---:|---:|---:|---:|---:|
| 43 | 1.25% | 12.42% | 11.33% | 5.00% | 70.00% |
| 44 | 0.40% | 17.23% | 7.36% | 18.16% | 56.84% |

元3内の比率は、それぞれの元3 clean-MSEと全件一致。元3総量は両seed25%で保持制約の境界、seed43のHGBも5%の境界に達した。RFは消していないが寄与は小さい。これは全5モデルが同じくらい有用だという証拠ではない。これらを平均して次runの固定重みにせず、学習側で同じ規則をfitする。[全方式の重み](weights.csv)。

### q100と、ExtraTreesだけの4モデル

clean6/11 q100は元3/HGB4/ExtraTrees4/5が315.47で同じ。6/18はseed43で元3=376.32、HGB4=322.11、ExtraTrees4=376.32、5=376.32。seed44はすべて434.02。**seed43の5モデルは回帰が良くてもHGB4の早いq100を失う。** −20の6/18はseed43で元3/HGB4=434.02に対し5=376.32、seed44は434.02不変。有限の評価chunkに対する到達段階としてFPと併記する。

ExtraTreesだけを足す4モデルとの差はclean RMSE−0.07/−0.11、FN−1/−1と小さい。seed43の−20ではExtraTrees4=75.35の方が5=76.31より良い。5は有望だが、5が4より必須・明確に優れるとは断定しない。[WAV単位bootstrap](wav_cluster_bootstrap.csv)の5対ExtraTrees4差はcleanで両seedとも95%区間が0を含む。これは既存開発データ条件付きの記述的な区間であり、反復開発や採用判断の不確かさを取り除くものではない。

### 領域と雑音劣化

5モデルのclean ONB近傍RMSEは35.20→18.62／27.84→17.09、ONB以上は41.91→21.78／39.31→24.32へ改善。一方、60未満は23.98→30.19／27.05→27.58と悪化。seed44の−20近傍も90.58→109.46へ悪化した。[領域別誤差](region_errors.csv)。

clean→−20のRMSE増加量は元3が45.67/47.52、5が51.64/48.31。**強雑音の絶対誤差は改善したが、cleanからの劣化量を小さくした証拠にはならない。** 元3のclean基準が悪いことを、雑音耐性の利点と読み替えない。ExtraTrees単体の−20 RMSE74.72/73.28は5より小さく、最良単体に対する雑音回帰の優位も確定していない。

## 6. 説明できたことと未確認の原因

**確認事実**：ExtraTreesはHGBとは違う共通失敗を訂正し、ExtraTreesの追加は元3に対してclean回帰と今回の強雑音の絶対誤差を両seedで良くした。最終木の不純度重要度は絶対power群77.67%/79.00%、相対周波数形状17.74%/17.68%に集中する。[構造的依存](extra_trees_dependence.csv)。時間power CVへの重要度は小さい。

**整合する仮説**：HGBの一部の分岐に依存した強雑音出力に対し、多数のランダム化木の平均が別の予測関係を与えている可能性がある。RF34の改善も、従来のPCA画像以外の要約入力の価値と整合する。

**未確認**：重要度は相関する特徴を含む分岐上の依存であり、powerの物理的音源や気泡発生を同定しない。ExtraTrees平均がHGBの誤報の原因そのものを解消したという因果説明も未確認。追加人手情報は得られない前提を維持する。

**次に識別する比較**：5モデルを通常runnerへ組み込む際に、同じ規則で元3＋ExtraTrees4を併記し、HGBを残す利得とq100/雑音回帰の代償を固定する。保持重み境界・HGBとExtraTreesの似た誤りが残るので、無制限のモデル数増加や新しいgateを自動追加しない。

## 7. 採用判断・実装・確認状態

研究上の主候補を**元3＋周波数HGB＋周波数ExtraTreesの5モデル、元3のclean-MSE内部比率を保持するclean OOF制約付き統合**へ更新する。元3＋ExtraTrees4を僅差の最有力対照、元3＋HGB4をq100の利点を持つ対照として保持する。前回のRF置換3モデルは履歴と無制約比較として残す。

5モデルの候補選択・学習・統合・保存・7条件評価は比較用入口で実装・実行済み。通常の`run_ensemble_regression_onb.py`の既定は元3のままで、今回の研究判断だけで通常runnerが5へ切り替わったとは扱わない。追加の承認・録音確認を次工程の条件にしない。

- 関連unittest3件通過。biased RFが無制約で外れる例でも保持比率を維持し、外側正解/予測を読まずに統合をfitでき、nested内部heldは対応fitから除外されることを確認。
- 元の4基礎モデルのOOF/外側配列を全件比較して完全一致。元3比率、全4/5メンバーの正の重み、外側/学習・内部fit/held非共有を確認。
- 保存72モデルのhash・再読込予測を全7条件で確認。648fit完了、3,654指標行のRMSE/MAE/R²/ONB領域/ROC・PR/FN/FP/Recall/Precision/F1と日別q100/g100を再計算して通過。[verification.json](verification.json)。
- 時間46特徴は過去のclean2,160入力と全件差0。原結果・学習環境・過去matchedは保持。
