# C：ピーク選別の対応比較と基準条件の判断

記録開始：2026-09-20。条件は実行前に[`2026-09-20_c_selection_pair.json`](../../configs/experiments/2026-09-20_c_selection_pair.json)へ固定した。[実行ラッパー](run_pair.py)は現行主コードの設定をメモリ上で上書きし、主コードを編集せずに2条件×3 seedを実行する。結果の標本別検算は[`analyze_pair.py`](analyze_pair.py)で行う。

## C1 実行前の条件と評価規則

問いは、学習6/11でONB以上の弱いピークを持つ秒を除くと、別日6/18への熱流束回帰とONB判定が改善するか。2条件の差はピーク選別の有無だけに固定する。選別ありは**2,100–2,500 Hz内の最大Welch PSD ≥1e-9**を保持し、選別なしは全学習秒を保持する。閾値は9/16に学習日の音を見て提案済みの探索値であり、6/18の予測精度から再調整しない。

共通条件は6/11学習、6/18の全18 WAV・1080秒評価、無雑音、22 kHz、RF＋Conformer＋AlexNet、各CNNの本学習と内部重み学習200 epochs、batch size 12、seed 42/43/44、元WAV分離の`inner_holdout`重み。PCA・目的変数scaler・重みは学習日だけでfitする。選別後の学習秒数と`ceil(秒数/12)×200`の名目上の本学習更新回数を記録する。選別で更新回数も減るため、改善が出た場合は同数ランダム除外を追加し、音響条件と標本数の影響を分ける。

評価は各モデルと保存された重み付き統合、事後計算の等重みで、全域R²/RMSE/MAE、ONB近傍RMSE、見逃し・誤報、同一WAVの二乗誤差差を読む。1秒chunkを指標の単位とし、同一WAVの60秒を独立反復60本とは数えない。判断は3 seedの対応差、領域別得失、ONB誤りを併記する。6/18でepoch・重み・選別閾値を決めない。

このC比較では過去runとの整合のため6/18のONB閾値を**271,677.6816 W/m²**、近傍を±10%とする。一方、[6/18原テキスト](../../Pool_boiling/Subcooling_20_degrees/0.3/2025.06.18_0.3_3/実験結果2025.06.18_0.3_3/2025.06.18_0.3_3.txt)は開始熱流束`3.76e+05 W/m²`と記す。6/11でもrun設定221,505.1102に対し[原テキスト](../../Pool_boiling/Subcooling_20_degrees/0.3/2025.06.11_0.3_2/実験結果2025.06.11_0.3_2/2025.06.11_0.3_2.txt)は`3.69e+05 W/m²`。原記録とrun閾値のどちらが物理的ONB判定として妥当か未確定。6/18の376,000でも感度分析し、物理的なONB成否の結論を分ける。選別そのものの適用範囲は**run設定の6/11閾値**に従うため、その値の意味が変われば選別集合も変わる。

**実行前に見つかった選別対象の違い**：Bの保存済み`training_selection_fold1.json`を監査すると、run設定の6/11閾値221,505.1102を使う選別では1080→986秒で、除外94秒は221,505のWAVで60秒、266,908で25秒、315,466で9秒。原テキストの開始値369,000以上で除外された秒は**0**。従って6/11のみのC1設定で「選別あり」にすると、実験記録上はONB前とされる音の弱い秒を削ることになる。原テキスト値を学習選別のONB閾値に採用する場合、この6/11比較は実質的に選別なし／ありの集合が同じとなり、選別効果を識別できない。現在の実行結果はあくまでrun設定値に条件を付けて読む。

なお、[9/17の閾値修正run](../2026-09-17_corrected_onb_threshold_run/README.md)は221,505.1102を設定値として明記し、この値を固定した選別なし／ありの対応比較を次の作業として提案している。C1はその提案を実行する。原テキスト値との違いを解消した物理的ONB比較ではない。

将来7/9を学習に追加する場合も、現行run設定は571,694.2525 W/m²だが[7/9原テキスト](../../Pool_boiling/Subcooling_20_degrees/0.3/2025.07.09_0.3_1/実験結果2025.07.09_0.3_1/2025.07.09_0.3_1.txt)は`4.42e+05 W/m²`と記す。同じ定義の違いを解決する前に、7/9追加と選別効果を一度に解釈しない。

## C4 独立評価と物理的正解の可否

[データ索引](../../docs/data_inventory.md)にある現行データは6/11、6/18、7/9の3実験日。7/9の音響特徴と熱流束は1e-9候補を決める過程で既に参照されているため、今回のピーク選別について**未使用の独立日**とは呼べない。6/18もA・Bの結果で研究方針を決めるのに既に使用している。本人への2026-09-20確認では、これら以外の未使用実験日データと音声同期の気泡観察映像は現時点で**ない**。

したがってC2で得るのは既存別日での探索的比較である。気泡発生秒の物理正解、未知日・未知水流音への一般化、音響による早期検知はこの結果だけでは主張しない。教授への確認事項は、(1) 新しい独立日で音・熱流束を取得できるか、(2) 気泡映像を音と同期できるか、(3) 原テキストのONB開始熱流束と最初のONB扱いWAVのどちらを物理基準にするか、(4) 回帰・見逃し・誤報の許容水準を用途からどう決めるか。新規取得ができなければ、修論での主張はこの3日・既存音源・run上の閾値に条件を限る。

### 確認事実・解釈・採否

確認事実は、現行run閾値の下で、選別がONB前の正方向バイアスを抑える一方、近傍1 WAVと近傍外ONB以上の誤差を全seedで増やしたこと。**選別1e-9はこの6/11→6/18・200 epochs条件の基準として採用しない**。C2の「改善したら同数ランダム除外」の開始条件は満たさず、対照runは追加しない。

整合する仮説は、run閾値の直後にある弱い音の94秒を外したことが、低域の過大予測軽減と近傍の過小予測増大の双方に寄与した可能性。しかし、モデル・標本数・更新回数が同時に変わり、3 seedは同じ学習日・評価日なので、単独原因や一般化効果は特定できない。今後、選別ルールを6/18の結果に合わせて改変して採用しない。

両条件のepochは事前固定の200であり、6/18で最良epochを選んでいない。学習側の元WAV分離`inner_holdout`は重み計算に使ったが、**epoch別の未知WAV validation曲線は今回も保存していない**。200 epochsの妥当性や過学習の有無はこの比較では判定できない。

## C3 統合重みの基準

今回の運用上の基準は、**学習6/11内の元WAV分離holdoutから計算する現行`inner_holdout`重みを維持**する。等重みはあらかじめ置いた固定対照として全runに事後適用した。選別なしでは重み付き統合のR²が3 seedとも等重みを上回るが、重みを選んだ理由をこの6/18成績には置かない。学習側だけで決まる現行方式を維持し、6/18でseed・条件ごとに勝者を選ぶ操作を避ける。重み付き統合も最良単体やRFのONB誤りを常に上回るわけではない。新しい重み方式の追加は保留し、等重み・単体を今後も併記する。将来重み方式を変更するなら、6/11側で元WAV分離の独立した方式選択比較を先に行い、新しい評価日で確認する。

## 次に進むための判断

まず教授と**ONB閾値の定義**を確定する。原テキストの6/11開始値369 kW/m²を選別適用下限にするなら、今回の6/11の94除外はすべて対象外となり、同日の1e-9選別あり／なしは同じ学習集合になる。追加の識別力を得るには、学習日を増やすか、別の学習側で定義した問いへ変える必要がある。7/9を増やす案では、その日のONB定義と、閾値1e-9を7/9の特徴を見て決めた履歴を明記し、6/18は探索的評価とする。独立日・同期映像は現時点でないため、新規取得の可否を教授へ相談する。

学習側の改善候補は、6/11内の元WAV分離validationでepoch別未知WAV誤差・ONB誤りを記録し、200 epochsとピーク選別の影響を学習側から診断すること。6/18を用いて最良epochや新しいピーク閾値を選ばない。今回のC2だけでピーク高さの物理的意味や一般化効果を確定しない。
